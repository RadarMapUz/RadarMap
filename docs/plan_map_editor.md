# Дорога как в образце: асфальт, разметка, полосы — и конструктор к ним

Переписан 25 августа 2026 по двум кадрам Яндекс.Навигатора, присланным
заказчиком.

Прошлая редакция отвечала на вопрос «как рисовать свои объекты поверх OSM».
Образец задаёт другой и более важный: **как получить саму картинку дороги** —
серое поле проезжей части с настоящей шириной, кромки, зебры, стрелки полос,
светофоры на своих местах. Конструктор в ответе остаётся, но он больше не
первый: замеры показали, что подавляющая часть образца не рисуется руками, а
считается, и считается из данных, которые уже лежат в том же `.pbf`, который
мы качаем каждое воскресенье.

---

## 0. Разбор образца по слоям

Что на кадре, чем оно является для рендера, и что из этого у нас уже есть.

| Слой на кадре | Чем является на самом деле | Что у нас сегодня |
|---|---|---|
| Серое поле проезжей части | осевая линия, нарисованная толщиной **в метрах** | линия толщиной в точках |
| Жёлтая/белая кромка проезжей части | обводка того же штриха | нет |
| Осевая разделительная | второй штрих поверх первого | нет |
| Зебры | поперечные штрихи в узле перехода | нет (в OSM есть) |
| Стоп-линии | поперечный штрих во всю ширину проезжей части | точка есть, азимута и ширины нет |
| Стрелки полос | по стрелке на полосу перед стоп-линией | нет |
| Светофоры | точка, привязанная к узлу перекрёстка | **есть** (наборы `p` и `q`) |
| Тротуары | отдельные тонкие линии | нет (в OSM есть) |
| Кварталы | полигоны | **есть** (набор `b`, считаются из самой сети) |
| Зелень, вода, рельсы | полигоны | **есть** (наборы `g`, `w`, `r`) |
| Здания и номера домов | полигоны с подписями | нет |
| Пробки | цвет вдоль маршрута | нет источника, см. §12 |
| Наклон камеры, перспектива | рендер, не данные | **есть** (схема уже наклонена) |

Пять слоёв из тринадцати уже едут на телефон. Вопрос не в том, чтобы
построить всё заново, а в том, чтобы добавить четыре: асфальт, разметку,
полосы и тротуары.

## 1. Замер: сколько из этого уже лежит в OSM

Overpass, центр Ташкента 4.5 × 5 км, тот же прямоугольник, на котором мерили
светофоры в прошлый раз (bbox `41.2886,69.2528,41.3336,69.3066`), 25 августа
2026. Проверка сходимости: светофоров насчиталось 321 против 318 в прошлом
замере — значит, меряем то же самое.

| Что | Сколько | Доля дорог |
|---|---|---|
| дорог всего (`way[highway]`) | 8 455 | — |
| с числом полос (`lanes`) | 769 | 9.1 % |
| **с шириной (`width`)** | **14** | **0.17 %** |
| с направлениями полос (`turn:lanes`) | 163 | 1.9 % |
| с полосами по направлению (`lanes:forward`) | 14 | 0.17 % |
| односторонних | 1 305 | 15.4 % |
| мостов | 133 | 1.6 % |
| зебры узлами (`highway=crossing`) | 809 | — |
| зебры линиями (`footway=crossing`) | 412 | — |
| тротуары (`highway=footway`) | 3 439 | — |
| светофоры | 321 | — |
| здания | 8 737 | — |

Из этой таблицы следует три вещи, и каждая меняет план.

**Ширину нельзя ни рисовать, ни читать.** Четырнадцать дорог из восьми с
половиной тысяч — это ноль. Ставить руками ширину каждой улицы города
невозможно; ждать, пока её проставит OSM, бессмысленно. Ширина **считается**
из класса дороги и числа полос — §5.1.

**Зебры и тротуары уже есть, и их много.** 809 узлов перехода, 412 линий
перехода и 3 439 тротуаров — это весь пешеходный слой образца, и он
скачивается за час ровно так же, как в прошлый раз скачались светофоры.
Рисовать переходы руками — это повторить ошибку, из-за которой прошлая
редакция начинала работу со светофора.

**Руками остаются ровно две вещи.** Число полос там, где OSM молчит (91 %
дорог), и направления полос (98 %). Всё остальное на образце — производная.

## 2. Открытие, которое меняет цену всей работы

**Проезжая часть — не полигон.**

Соблазн смотреть на серое поле образца как на геометрию: посчитать границы,
объединить перекрытия, разрезать на перекрёстках. Так делать не надо, и дело
не в экономии, а в том, что булева геометрия здесь просто не нужна.

Асфальт — это **та же осевая линия, нарисованная толщиной в метрах вместо
толщины в точках**. Перекрёсток собирается сам: два широких штриха,
пересекаясь, дают ровно то поле, которое видно на образце. Скругления на
поворотах даёт `lineJoin`, торцы — `lineCap`. Ни одного пересечения полигонов
не считается ни на сервере, ни на телефоне.

Клиент так уже умеет: `RoadSketchView` рисует сеть штрихами и знает про
`strokeScale`. Меняется одно — толщина берётся не константой, а переводом
метров в точки через текущий масштаб схемы.

Из этого следует главное для формата: **данных прибавляется одно число на
дорогу** — число полос. Не полигон, не новый слой геометрии, не новый набор
тайла. Одно число.

Порядок отрисовки на тик (снизу вверх):

```
кварталы, зелень, вода      ← уже есть
асфальт (широкий штрих)     ← новое, тот же массив линий
кромка (обводка штриха)     ← новое, тот же массив
разметка: зебры, стоп-линии ← новое, набор точек
осевые линии сети           ← уже есть, теперь поверх асфальта
стрелки полос               ← новое, набор точек
точки: светофоры и прочее   ← уже есть
```

Три новых прохода по УЖЕ разобранному массиву дорог и один по точкам.
Ни одной новой структуры данных в памяти.

## 3. Найденная ошибка: «пятый элемент» обнулил бы тайл целиком

Прошлая редакция предлагала возить полосы «пятым элементом записи дороги».
Так делать нельзя, и это проверяется одной строкой:

```swift
// RadarMap/Models/RoadTiles.swift:193
guard entry.count == 3 || entry.count == 4,
```

Запись из пяти элементов не расширяет формат — она роняет разбор **всего
тайла**: `decodeEntries` возвращает `nil`, и установленная сборка теряет не
одну дорогу, а весь квадрат целиком. Ровно та же ловушка, что и с индексом
чужой версии, из-за которой формат v1 до сих пор собирается параллельно с v2.

**Полосы едут битами 4–7 поля `flags`.** Старые сборки читают `flags`
масками — `& 1`, `& 2`, `& 4`, `& 8` (`RoadTiles.swift:223`) — и старших битов
просто не видят. Четыре бита дают 0–15 полос, чего хватает с запасом: ноль
означает «OSM молчит, считай по классу».

| Биты `flags` | Значение |
|---|---|
| 1 | одностороннее |
| 2 | мост |
| 4 | тоннель |
| 8 | кольцо |
| **16, 32, 64, 128** | **число полос, 0–15 (0 = не задано)** |

Ни один файл не меняет формы, ни одна установленная сборка ничего не теряет,
и новый клиент получает полосы в тот же день, когда выкатится генератор.

## 4. Законы

**Закон 1. Свой слой не трогает OSM.** База пересобирается из свежего
экстракта каждое воскресенье; любая правка «внутрь» будет стёрта следующим
прогоном. Решения копятся в `overrides`, накладываются при публикации. Приём
проверен на камерах.

**Закон 2. Ничего не публикуется из панели.** Правки копятся в таблице;
подписывает и выкладывает владелец со своей машины (`publish_roads.sh`,
`publish_overrides.sh`). Взломанный VPS не должен уметь дорисовать дорогу
телефонам. Не обсуждается.

**Закон 3. Автоматика чинит только то, что может проверить.** Сдвиг на два
метра после обновления OSM — чинит сама. Дорога, к которой правка была
привязана, исчезла — спрашивает. Граница в §9.

**Закон 4 (новый). Сначала считаем, потом рисуем.** Ни один вид объекта не
попадает в конструктор, пока не доказано, что его нельзя получить из OSM или
вывести из того, что уже есть. Этот закон появился дважды: сначала на
светофорах (1 899 штук скачались за час вместо ручной разметки), теперь на
зебрах и тротуарах (4 660 объектов). Третьего раза быть не должно.

## 5. Что считает генератор

Всё в этом разделе — `build_roads.py`, ноль ручного труда, покрытие города
целиком с первого прогона.

### 5.1. Ширина проезжей части

```
ширина = полосы × ширина_полосы × (одностороннее ? 1 : 2)
```

Число полос — из `lanes`, если тег есть (9 % дорог), иначе по классу:

| Код | Класс | Полос в сторону | Ширина полосы |
|---|---|---|---|
| 1 | motorway | 3 | 3.75 м |
| 2 | trunk | 3 | 3.75 м |
| 3 | primary | 3 | 3.75 м |
| 4 | secondary | 2 | 3.5 м |
| 5 | tertiary | 2 | 3.5 м |
| 6 | residential | 1 | 3.5 м |
| 7 | service | — | 4.5 м всего |

Проверка на образце: проспект Алишера Навои — `primary`, разделённая
проезжая часть, то есть в OSM две односторонние линии. Каждая получает
3 × 3.75 = 11.25 м, между ними разделительная. Именно две серые ленты с
разрывом посередине и видно на кадре. Двор — 1 × 3.5 × 2 = 7 м. Оба числа
сходятся с натурой без единой правки руками.

**Дальний набор — особый случай.** В наборе `f` раздельные проезжие сведены
в одну ось (см. `split_sets`), и брать ширину одной из них значит нарисовать
проспект вдвое уже, чем он есть. Ширина костяка — **сумма** сведённых
проезжих плюс разделительная.

### 5.1.1. Разделительные: как их рисовать, не трогая геометрию

Разделительная между полосами — линия, параллельная оси и отстоящая от неё на
известное число метров. Честный способ — сместить ломаную вбок; он стоит
(полос − 1) новых ломаных на каждую дорогу, и это на самом плотном слое схемы.

Способ дешевле берётся из того же наблюдения, что и §2. Штрих шириной 2d,
положенный на готовое полотно цветом разметки и тут же перекрытый асфальтом
шириной 2d − t, оставляет ровно две линии на ±d от оси — пару разделительных.
Два штриха по УЖЕ ГОТОВОМУ пути, ни одной новой точки. Пунктир задаётся
внешнему штриху: в его разрывах остаётся асфальт, и линия выходит прерывистой
сама собой.

Порядок — от края к центру: широкий штрих закрывает всё, что лежит внутри
него, и обратный порядок стирал бы уже нарисованное.

Разделительные кладутся ДО заглушек узлов. Заглушка кладёт в узле диск цветом
асфальта, то есть стирает разметку ровно там, где ей и положено обрываться, —
перед перекрёстком.

### 5.2. Асфальт и кромка

**Выяснилось при реализации: этих проходов писать не надо, они уже есть.**
`SketchRaster` рисует сеть ровно так, как описано выше: сначала все каймы,
потом все полотна, потом заглушки узлов в местах стыка. Не хватало ровно
одного — ширина бралась в пунктах по классу, а не в метрах.

Поэтому нулевой этап свёлся к одной формуле: толщина штриха берётся
максимумом из метрической ширины (`полосы × ширина_полосы × k`) и прежней
формулы в пунктах. Порога по охвату нет намеренно — см. §11.

### 5.3. Зебры

Источник — `highway=crossing` (узлы) и `footway=crossing` (линии). Узел даёт
точку, линия — точку и **азимут**, и азимут дороже: зебра, нарисованная без
него, ляжет вдоль дороги вместо поперёк. Там, где есть только узел, азимут
берётся от дороги, к которой узел принадлежит, — перпендикуляром к её оси в
этой точке.

Ширина зебры — ширина проезжей части из §5.1. Она уже посчитана, и это ещё
одна причина считать ширину, а не рисовать.

### 5.4. Стоп-линии

Точки уже есть (`POINT_STOP_LINE`), но в тайле у них нет ни азимута, ни
ширины — то есть нарисовать их нечем. Добавляем то же, что зебрам:
перпендикуляр к оси и ширина проезжей части. Азимут — в биты `flags` записи
точки, шагом 3° (0–119 в семи битах): точнее не нужно, поперечная линия
ошибку в полтора градуса не показывает.

### 5.5. Стрелки полос

Единственный слой, который на 98 % придётся ввести руками, — и потому
последний по очереди, а не первый. Из OSM берётся `turn:lanes` там, где он
есть (163 дороги). Стрелки ставятся перед стоп-линией, по одной на полосу,
шагом в ширину полосы от кромки.

### 5.6. Тротуары

`highway=footway` — 3 439 линий в центре. Новый набор тайла `t`, по тому же
закону, что вода и зелень: свой файл, своя полоса охвата, не качается, пока
не виден. Виден ближе 150 м — дальше тротуар неотличим от кромки.

## 6. Что остаётся рисовать руками

После §5 список короткий, и это его главное свойство.

| Вид | Почему не считается | Объём |
|---|---|---|
| Число полос | OSM молчит у 91 % дорог; по классу — приближение | правится точечно, там, где приближение врёт |
| Направления полос | OSM молчит у 98 % | перекрёстки, где ошибка полосы стоит разворота |
| Разворот: можно/нельзя | тега нет вовсе | десятки на город |
| Своя геометрия | дороги нет в OSM | единицы, §7.4 |

Обратите внимание, чего в списке НЕТ: светофоров, зебр, стоп-линий,
тротуаров, ширины, односторонности, мостов. Всё это считается.

## 7. Конструктор в панели

### 7.1. На чём строится

Ничего нового ставить не нужно — вся оснастка уже стоит на VPS.

| Что нужно | Что уже есть |
|---|---|
| Карта со спутником | Яндекс.Карты JS 2.1 в `/map`, ключ в конфиге (`admin.py:612`) |
| CSP под неё | `CSP_MAP`, послаблена ровно на одной странице (`admin.py:789`) |
| Свой скрипт файлом | `static/moderate.js`, 288 строк, без сборки и фреймворков |
| JSON-ручки | `/api/cameras`, `/api/camera/<id>`, `/api/move`, `/api/undo` |
| Перетаскивание точки с сохранением | `ymaps.Placemark` + `/api/move`, работает |
| Хранилище решений | sqlite + таблица `overrides` |
| Публикация вне панели | `publish_overrides.sh` с машины владельца |

Конструктор — это `/editor` рядом с `/map` и `static/editor.js` рядом с
`moderate.js`. Та же страница, та же CSP, тот же стиль: серверный HTML,
один свой скрипт, никакой сборки. Панель модерируют с телефона между делом —
это решение принято и менять его незачем.

Подложка Яндекса здесь — не совпадение, а удобство: образец, по которому
сверяются, нарисован ею же.

### 7.2. Две подложки, и вторая важнее

**Спутник** — чтобы видеть правду: где на самом деле стоит светофор и куда
на самом деле ведёт полоса.

**Наш собственный рендер схемы** — чтобы видеть, что увидит водитель. Тот же
код ширин из §5.1, те же цвета, тот же порядок слоёв. Без него правишь
вслепую: полоса, идеально поставленная по спутнику, на схеме может оказаться
под кромкой или за краем охвата.

Переключение — одной клавишей, обе подложки в одном масштабе.

### 7.3. Порядок работы

1. Вид объекта — панель слева, горячие клавиши 1–9.
2. Курсор ведёт — магнит подсвечивает дорогу, к которой прилипнет, и рисует
   призрак объекта в том виде, в каком он попадёт на телефон.
3. Клик — объект создан со статусом «черновик».
4. Карточка справа: свойства по виду, обязательное «почему» для своей
   геометрии, «принять».
5. Перетаскивание — объект переставляется, магнит работает так же.
6. Delete — статус «снято», не удаление.

Чего в редакторе не будет: свободного рисования без магнита (кроме явного
режима «вне дороги»), массовых операций без предпросмотра списка, и
публикации — закон 2.

### 7.4. Своя геометрия

Дорога, которой нет в OSM, иногда нужна: OSM догонит не завтра, а ездить по
ней сегодня. Не запрещаем, а обставляем:

1. Всегда помечена и всегда видна в панели отдельным цветом.
2. Обязательное «почему»: нет в OSM / OSM неверен / временная схема.
3. Срок пересмотра: временная схема — 90 дней, «нет в OSM» — 180.
4. Панель сама предложит снять, когда OSM догонит (§9.3).
5. Кнопка «отправить в OSM»: геометрия в формате, который остаётся вставить
   в редактор. Дорога, отданная в OSM, поддерживается всем миром, наша —
   только нами.

## 8. Магнит

То, ради чего конструктор имеет смысл: объект, поставленный на глаз,
промахивается на десяток метров, и на схеме окажется в поле.

Магнитится **к оси дороги из наших же тайлов** — не из Яндекса и не из
сырого OSM. В панели видно ровно ту геометрию, которая поедет на телефон,
вместе со всей генерализацией.

| Порог | Значение | Почему |
|---|---|---|
| Радиус захвата | 25 м | дальше это уже не «на дороге» |
| Захват узла | 15 м | светофоры и стоп-линии стоят на перекрёстках |
| Неоднозначность | 3 м | две дороги ближе трёх метров — не гадаем |
| Мягкий магнит | 6 м | ближе — тянет, дальше курсор свободен |

1. В радиусе захвата — прилипает к **проекции на ось**, не к ближайшей
   вершине: между вершинами бывает сотня метров.
2. В радиусе узла — к **узлу перекрёстка**.
3. Две дороги на равном удалении — **магнит не решает за человека**: обе
   подсвечиваются, объект не ставится до выбора. Типичный случай — проспект
   с дублёром, и угадывание там даёт разворот не с той проезжей части.
4. Дальше радиуса — точка ставится свободно и помечается «вне дороги».
   Ворота публикации о ней спросят.

Поиск — по сеточному индексу, ячейка 0.01°, тем же приёмом, что
`attach_to_junctions` в `build_roads.py`.

### 8.1. Что сохраняется

Три вещи, и все три нужны:

- **`raw`** — куда человек ткнул на самом деле;
- **`snapped`** — куда магнит посадил;
- **`anchor`** — описание дороги без её id: класс, азимут в точке, имя,
  отпечаток окрестной геометрии.

`raw` хранится ради §9: когда OSM обновится, пересаживать объект надо от
исходного намерения человека, а не от прошлой посадки — иначе объект уползает
понемногу каждую неделю.

## 9. Когда OSM обновился

### 9.1. Таблица

```sql
CREATE TABLE map_edits(
  id           INTEGER PRIMARY KEY,     -- свой, никогда не из OSM
  kind         TEXT NOT NULL,           -- lanes | turn_lanes | u_turn | geometry | …
  status       INTEGER NOT NULL,        -- 0 черновик 1 принято 2 опубликовано 3 снято
  geom         TEXT NOT NULL,           -- JSON: точка или ломаная (snapped)
  raw          TEXT NOT NULL,           -- JSON: куда ткнул человек
  anchor       TEXT,                    -- JSON: класс, азимут, имя дороги
  props        TEXT,                    -- JSON: по виду объекта
  fingerprint  TEXT,                    -- хэш окрестной геометрии OSM
  note         TEXT,                    -- зачем; через полгода спасёт только это
  author       TEXT NOT NULL,
  created      INTEGER NOT NULL,
  updated      INTEGER NOT NULL,
  version      INTEGER NOT NULL         -- оптимистическая блокировка
);
CREATE INDEX idx_edits_tile ON map_edits(kind, status);
```

История не удаляется: `status = 3` вместо `DELETE`. Ручная работа —
единственные данные в системе, которые нельзя восстановить пересборкой.

### 9.2. Что делает автоматика сама

Еженедельная сборка считает `osm_diff.json`: появившиеся дороги, исчезнувшие,
сдвинувшиеся больше чем на 5 м, и сошёлся ли отпечаток у каждой нашей правки.

| Что случилось | Действие |
|---|---|
| Отпечаток сошёлся | ничего, правка едет дальше молча |
| Сдвиг ≤ 3 м | пересаживаем от `raw`, пишем в лог |
| Сдвиг 3–15 м | пересаживаем, помечаем «проверить», публикуем |
| Сдвиг > 15 м | снимаем с публикации, в очередь |
| Дорога исчезла | снимаем с публикации, в очередь |
| Рядом с нашей нарисованной появилась настоящая (< 20 м) | в очередь: «OSM догнал» |

Граница одна: **автоматика вправе двигать объект, но не вправе решать, что он
больше не нужен.**

### 9.3. Страница «Что изменилось»

Новая вкладка панели, по важности сверху вниз:

1. **OSM догнал нас** — обе дороги на карте, одной кнопкой «снять свою».
2. **Правки, потерявшие опору** — дорога исчезла или уехала далеко.
3. **Правки, пересаженные автоматикой** — просто список, чтобы видеть.
4. **Новое и исчезнувшее в OSM по районам** — фон, чтобы замечать крупное.

Ничего не применяется само. Один клик — и правка снята, подтверждена или
перенесена.

## 10. Ворота публикации

К `roads_gate.py` добавляются свои. Числа ловят опечатку, а не мешают работе.

| Проверка | Порог |
|---|---|
| Объект дальше от любой дороги | 30 м → стоп |
| Светофор не на узле | предупреждение |
| Разворот на односторонней | стоп |
| Полос меньше 1 или больше 15 | стоп (больше в биты не влезет) |
| Своя дорога короче | 20 м → стоп |
| Отпечаток не сошёлся | не публикуется до проверки |
| Изменилось правок за раз | > 200 → стоп и вопрос |
| Объектов в одном тайле | > 500 → стоп: похоже на клик-спам |
| **Ширина проезжей части** | **> 60 м → стоп: опечатка в полосах** |

Правка, не прошедшая ворота, не пропадает: остаётся в таблице и попадает в
очередь.

## 11. Производительность: чем за это платит телефон

Раздел не формальный. Схема существует ровно затем, чтобы НЕ быть полным
векторным рендером: MKMapView выгружается целиком, тайлы и аннотации
перестают греть телефон в держателе. Образец же — как раз полный векторный
рендер. Противоречие настоящее, и разрешается оно одним правилом.

**Каждый вид — свой набор, своя полоса охвата, своя ступень перегрева.**
Так уже живут дворы, вода, зелень, рельсы, кварталы и точки; новые слои
входят тем же способом и ни на метр дальше:

| Слой | Виден ближе | Почему не дальше |
|---|---|---|
| Асфальт (ширина в метрах) | без порога, см. ниже | — |
| Кромка проезжей части | 150 м | дальше сливается с асфальтом |
| Разделительные полос | полоса ≥ 6 пт на экране | тоньше — рябь, а не пунктир |
| Зебры | 120 м | дальше это пиксель |
| Стоп-линии | 150 м | нужна ровно на подъезде |
| Стрелки полос | 120 м | решение о полосе принимают здесь |
| Тротуары | 150 м | дальше неотличимы от кромки |

**У асфальта порога нет, и это не исключение из правила, а его следствие.**
Метрическая ширина берётся МАКСИМУМОМ с прежней формулой в пунктах, а на
дальнем охвате они сходятся сами: проспект в 22.5 м при 0.47 пт/м даёт 10.6
пт против 11.5 пт по классу. То есть на костяке ничего не меняется вовсе,
порог городить не за чем, и границы, на которой ширина прыгает, не
существует. Прежняя формула остаётся полом: дорога, честно суженная вместе с
масштабом, на семистах метрах стала бы волосом.

Остальное — уже действующие правила, и они не смягчаются:

1. **Пиктограммы объявлены символами Canvas** — растеризуются один раз,
   дальше копируются. Сто зебр стоят одной растеризации.
2. **Ничего в `RebuildKey`, что меняется чаще растра.** Не нарушалось ни разу.
3. **Бюджет на вид в тайле.** Больше порога — режем по близости.
4. **Пиктограммы не запекаются в растр.** Растр целиком поворачивается по
   курсу, и запечённая стрелка полосы ляжет набок на повороте. Точечные слои
   едут своим слоем в координатах мира, с возвращённым курсом.
5. **Три новых прохода — по уже разобранному массиву.** §2: новых структур в
   памяти нет.

## 12. Чего в плане нет и почему

**Пробки.** На образце они есть, у нас источника нет: ни своего потока
скоростей достаточной плотности, ни лицензии на чужой. Появится своя
телеметрия достаточного объёма — вернёмся; до тех пор цветная лента вдоль
маршрута будет враньём, а вранью на приборной панели не место.

**Здания и номера домов.** В OSM есть (8 737 в центре), но это самый дорогой
слой по числу объектов и самый бесполезный за рулём: водитель едет по
дороге, а не по подъездам. После §5 — не раньше.

**Голосовые названия улиц и полос.** Отдельная работа, к картинке отношения
не имеет.

|---|---|---|
| ~~**0. Асфальт насквозь**~~ | **сделано**: полосы из OSM и по классу, биты 4–7 `flags`, потолок полос по классу на обоих концах, метрическая ширина в рендере | — |

| 3. Тротуары | новый набор `t`, тем же способом, что вода | день |
| 4. Конструктор: полосы | `/editor`, магнит, таблица, экспорт, запекание, ворота | 3 дня |
| 5. Очередь изменений OSM | `osm_diff.json`, «Что изменилось», авто-пересадка | 2 дня |
| 6. Стрелки полос | `turn:lanes` + ручной ввод в конструкторе | 2 дня |
| 7. Разворот и своя геометрия | с пометкой, «почему», сроком, «отправить в OSM» | 2–3 дня |
| 8. Камеры переезжают в конструктор | один инструмент вместо двух | день |

**Порядок не переставлять.**

Нулевой этап — не про асфальт, а про то, что картинка образца начинается с
ширины: без неё нечем нарисовать ни зебру, ни стоп-линию, ни стрелку полосы,
потому что все три меряются шириной проезжей части.

Этапы 0–3 дают процентов восемьдесят образца и **не требуют ни одного
ручного клика**: город покрывается целиком с первого воскресного прогона.
Конструктор идёт четвёртым именно поэтому — сначала надо увидеть, что
осталось после автоматики, и только потом строить инструмент под остаток.

Этап 5 стоит делать раньше шестого, хотя он и скучнее: без очереди изменений
слой начнёт тихо расходиться с OSM с первого же воскресенья, и через месяц
никто не вспомнит, что где нарисовано.
