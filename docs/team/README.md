# Команда RadarMap

Семь ролей — постоянные агенты проекта (`.claude/agents/`). Ведущий —
основная сессия: раздаёт задачи, сводит ответы ролей в одно решение, показывает
владельцу, сливает в `main`. Владелец решает по картинкам и коротким вариантам.

| Роль | Агент | Отвечает за |
|---|---|---|
| Идеи | `product-ideas` | что сделать: боли водителя, конкуренты, гипотезы с оценкой |
| Дизайнер | `ui-pro-designer` | как это выглядит и ощущается: экраны, CarPlay, часы, варианты A/B/C |
| Картограф | `cartographer` | карта и геоданные: стиль, дороги, полосы, привязка точек к дороге |
| CarPlay | `carplay-specialist` | экран машины: шаблоны, сессия навигации, плитка, баннеры, правила Apple, чек-лист для машины |
| Маркетолог | `growth-marketer` | зачем это человеку и как он узнает: тексты, App Store, сообщество |
| Инженер | `radarmap-engineer` | реализация по спецификации, тесты |
| Ловец багов | `bug-hunter` | сломать до водителя: ревью веток, сценарии отказа, регрессии |

## Как идёт задача

1. **Разбор** — ведущий раздаёт задачу ролям, которых она касается, параллельно.
   Каждая роль пишет короткое предложение в свою подпапку scratchpad
   (`<scratchpad>/<задача>/<роль>.md`), не код.
2. **Сводка** — ведущий сводит предложения в одну спецификацию
   `docs/team/specs/<задача>.md`: что делаем, варианты (если нужен выбор
   владельца), что не делаем и почему, критерии готовности.
3. **Выбор** — владелец выбирает вариант. Без выбора внедрения нет.
4. **Реализация** — инженер (UI — вместе с дизайнером, карта — с картографом)
   в своей ветке и рабочей копии.
5. **Проверка** — ловец багов читает ветку как противник: ищет, где сломается,
   а не подтверждает, что работает. Находки — в ветку инженеру, до слияния.
6. **Слияние** — ведущий: дифф, тесты, план, `main`. Пуш и выкладка — только
   по слову владельца («пушь», «катим», testflight).

Идеи и баги, не привязанные к задаче, роли складывают в `docs/team/ideas.md` и
`docs/team/bugs.md` (через ветку, как всё остальное). Ведущий разбирает их в план.

## Общие правила для всех ролей

- Прочитай `CLAUDE.md` и `ARCHITECTURE.md` до работы.
- **Оповещения о камерах не трогать** (`LocationGates`, `AlertEngine`,
  `AlertPolicy`, `RoadCorridor`, `LocationFilter`, `PassTracking`, `AlertPlayer`):
  молчание о настоящей камере хуже лишнего предупреждения. Громкость и подачу
  голоса не понижать.
- **Своя ветка и своя рабочая копия**: `git worktree add ../<задача> -b plan/<задача>`
  от свежего `main` в `~/Zafar/RadarMap-wt/`. Общую папку `~/Zafar/RadarMap` не трогать.
- **Сборка**: `xcodebuild` запрещён. Есть `mcp__xcode__*` — ими; нет — проверка
  типами по памяти проекта (`swiftc -typecheck -default-isolation MainActor`,
  MapLibre через `-F`), в отчёте «проверено typecheck», не «собрано». Чистую
  логику можно выполнить в macOS-бинарнике. Серверные тесты — `python3 -m unittest`.
- **Симулятор** — только свой UDID из задания, никогда `booted`; загружать, если
  загружено не больше одного; SpringBoard упал — одна перезагрузка; в конце выключить.
- **Коммиты** — одна строка Conventional Commits по-русски
  (`fix(itogi): …`), без тела и трейлеров; в коммит только свои файлы.
  Не пушить, не выкатывать, testflight/* не трогать.
- **Строки** — `String(localized:)` + `Shared/Localizable.xcstrings`, ru и uz;
  каталог правится скриптом, только свои ключи.
- **Приватность**: дом, работа, маршруты и время выезда не уходят на сервер.
- Телефон владельца — iPhone 16 Pro; узкая проверка — iPhone SE (375 pt).
  Каждый экран — на узбекском тоже (строки на 20–40 % длиннее).
- Отчёт — по-русски, коротко, с путями к файлам и снимкам; неуверенность
  называть прямо.

## Автономный цикл

Команда улучшает приложение сама, без задачи от владельца. Один цикл:

1. **Обход** — параллельно, только чтение:
   - идеи: 3–7 идей с оценкой ICE;
   - дизайнер: три самых слабых места интерфейса;
   - картограф: три самых заметных дефекта карты;
   - маркетолог: тексты и путь нового водителя;
   - ловец багов: охота по последним слияниям и по самому важному потоку.
2. **Отбор** — ведущий берёт 1–3 пункта с наибольшей пользой для водителя на
   цену и пишет спецификацию. Вкусовой выбор (вид экрана, палитра, тон текста) —
   варианты владельцу; остальное решает ведущий по рекомендации ролей.
3. **Реализация и проверка** — инженер, затем ловец багов, затем слияние в
   локальный `main`.
4. **Отчёт владельцу** — что сделано, что ждёт его слова (пуш, «катим»,
   TestFlight, выбор варианта). Следующий цикл начинается без ожидания, если
   владелец не остановил.

Без слова владельца цикл никогда не пушит, не выкатывает на сервер, не
публикует данные и не отправляет сборку в TestFlight.
