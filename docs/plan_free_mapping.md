# План: реальная разметка перекрёстков — бесплатно и законно

Написан 06.10.2026. Выбранная связка: **обводка в OSM по снимкам Bing/Esri**
(главное) + **Mapillary с телефона** (знаки и стрелки) + **наш редактор** в
админке (доводка). Платные снимки и своя нейросеть по ним — позже, если
понадобится масштаб на всю страну (`docs/plan_imagery_ml.md`).

Почему так: наша сборка уже читает из OSM всё нужное — `lanes`,
`turn:lanes`, `width`, переходы, островки, `area:highway`. Каждая правка в OSM
через неделю (воскресный `update_roads.sh`) сама приезжает на карту и на
телефоны. Снимки Bing и Esri разрешено использовать для правок OSM; снимки
Google/Яндекса/2ГИС — нельзя ни в каком виде.

## Шаг 0. Подготовка (полдня, владелец)

- Аккаунт на openstreetmap.org (создаёт владелец сам).
- Редактор: **iD** (в браузере, проще) или **RapiD** (тот же iD + подсказки
  ИИ от Meta: оси дорог, найденные нейросетью, принимаются кликом).
- Подложка в редакторе: «Bing aerial» или «Esri World Imagery» — сравнить,
  где Ташкент свежее/чётче; если снимки расходятся, верить свежему.
- Правила сообщества OSM: комментарий к пакету правок («Ташкент: полосы и
  переходы на перекрёстке X»), источник `source=Bing` / `Esri`, без массовых
  автоматических заливок — всё руками.

## Шаг 1. Очередь перекрёстков (готово)

`server/junction_worklist.py` — список перекрёстков Ташкента, где в OSM не
хватает данных, по важности: вес примыкающих магистралей × недостача (куски
без `lanes`, нет `turn:lanes`, меньше двух переходов). У каждой строки ссылка
«открыть в iD / RapiD».

    python3 server/junction_worklist.py roads.geojsonl points.geojsonl --html worklist.html

Первые места (06.10.2026): Малая кольцевая × Корасарой, × Чингиз Айтматов,
Миробод × Шахрисабз × Руставели, **Беруни × Малая кольцевая** (снимок
владельца), Чиланзар × Домбиробод, Ахмад Дониш × Юнусота, Беруни ×
Сакичмон (Чорсу)… — 100 перекрёстков в списке.

## Шаг 2. Что ставить на каждом перекрёстке (шпаргалка, ~10–15 минут на перекрёсток)

| Что | Тег | Как наша карта это рисует |
|---|---|---|
| Число полос каждого куска | `lanes=3` (на двусторонней — ещё `lanes:forward/backward`) | пунктир полос, ширина полотна |
| Стрелки на подходе | `turn:lanes=left|through|through;right` на последнем куске перед узлом | ряд стрелок перед стоп-линией |
| Раздельные направления | две односторонние линии вместо одной, где есть разделительная | разделительная полоса с бордюром |
| Переход | линия `highway=footway` + `footway=crossing` + `crossing=marked` (или `zebra`) от бордюра до бордюра | зебра поперёк подхода, в ширину полотна |
| Островок | замкнутый контур `area:highway=traffic_island` | островок поверх асфальта с бордюром |
| Светофор | точка `highway=traffic_signals` на подходе у стоп-линии | стоп-линия, «вафля» узла |
| Ширина, если необычная | `width=14` | ширина полотна по факту |

Порядок на перекрёстке: сначала разделить направления и поставить `lanes`,
потом `turn:lanes`, потом переходы и островки.

## Шаг 3. Mapillary с телефона (знаки, стрелки, проверка)

- Приложение Mapillary в держателе на обычных поездках (минут 30 в день по
  магистралям из очереди).
- Mapillary сам распознаёт знаки, стрелки на асфальте, переходы; в iD есть
  слой «Mapillary» — по нему видно, какие стрелки на подходе на самом деле, и
  это ставится в `turn:lanes`.
- Знаки (ограничения скорости, запреты поворота) — отдельная ценность для
  алертов и лимитов: проверять `maxspeed` по фото.

## Шаг 4. Наш редактор перекрёстка в админке (1–1,5 недели, я)

Для того, что в OSM не ложится или нужно срочно: шаблон перекрёстка, кромка в
4–6 кликов, разделительная «полосой N м», полосы и стрелки по подходу, зебра
и стоп-линия одним кликом. Сохраняется в `edits.json` (ручные правки уже
поддерживаются сборкой, флаг `FLAG_HAND_DRAWN`), публикуется подписью
владельца, как сейчас. Подложка — только наша карта.

## Шаг 5. Еженедельный цикл

1. Правки в OSM за неделю (по очереди сверху вниз).
2. Воскресенье: `update_roads.sh` собирает страну, ворота метрик проверяют,
   что не стало хуже.
3. Владелец публикует (`publish_roads.sh --auto`).
4. Очередь пересчитывается — сделанные перекрёстки уходят из неё; видно
   прогресс: «из 100 перекрёстков данных хватает у N».

## Сроки и ожидания

- 20 главных перекрёстков — первая неделя (по ~15 минут каждый).
- 100 перекрёстков — месяц в спокойном темпе.
- Улучшение видно на карте через неделю после правки; правила сборки
  (`docs/plan_junctions_polish.md`) параллельно улучшают все перекрёстки страны.
