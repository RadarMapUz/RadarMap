# Архитектура RadarMap

Паттерн — **MV (Model–View)**, родной для SwiftUI: без ViewModel-прослоек,
вьюхи читают наблюдаемые модели напрямую. Документ фиксирует правила,
по которым пишется и ревьюится код.

## Слои

```
View (SwiftUI)  →  @Observable модели/сервисы  →  чистые функции домена
      ↑                    ↑                              ↑
 только разметка   состояние + оркестрация      вся математика, тестируемая
 и локальный       (MainActor)                  (nonisolated static)
 UI-state
```

- **Композиционный корень** — `AppEnvironment` (`App/AppEnvironment.swift`):
  создаёт все сервисы один раз, связывает их и раздаёт через
  `.environment(...)`. Телефонная сцена и CarPlay делят один экземпляр
  (`AppEnvironment.shared`).
- **View** — только разметка, анимации и локальный UI-state
  (`@State` для флагов шитов, выбранных элементов). Никаких вычислений над
  доменными данными: группировки, агрегаты, фолбэки живут в моделях.
- **Модель/сервис** — `@MainActor @Observable final class`. Состояние
  `private(set)`, мутации через методы. Скрины-состояния экранов
  (например, `MapState`) — тоже модели, а не «ViewModel»: они не
  форматируют данные для вью, а владеют состоянием экрана.
- **Чистые функции** — `nonisolated static` (`DrivingScore`,
  `FineSchedule`, `TripStats.pruned/sanitized`, `LocationService.measuredSpeed`).
  Всё, что можно посчитать без ссылок на сервисы, пишется так — это
  единственный слой, который покрывается юнит-тестами напрямую.

## Правила

1. **Данные вниз, действия вверх.** Вью не пишет в чужое состояние —
   зовёт метод модели. Колбэки между сервисами — через слабые замыкания,
   выставленные в `AppEnvironment`.
2. **Протокол — только там, где нужна подмена** (репозиторий камер —
   `CameraRepository`). Не плодим протоколы «на всякий случай».
3. **Ошибки не глотаются.** Либо `Log.<подсистема>.error(...)`, либо
   комментарий, почему молчание — осознанное решение. Голых `try?` без
   одного из двух не бывает.
4. **Константы — в `AppConfig`** с комментарием, почему значение такое.
   Магические числа в коде запрещены.
5. **UserDefaults — только через `Storage`** (типизированные ключи).
   Исключение — `AppSettings`: настройки живут за собственным типизированным
   фасадом (`Keys` + `register(defaults:)`). Прямых строковых ключей в коде нет.
6. **Сеть — только через `APIClient`**: базовый URL, таймауты, проверка
   статуса, декодирование и лог в одном месте.
7. **Локализация**: пользовательские строки — `LocalizedStringKey` или
   `String(localized:)`. Тернарники строковых литералов внутри `Text()`
   запрещены (обходят локализацию). Числа — `String(format:locale:.current)`.
8. **Батарея — приоритет №1.** Повторяющиеся анимации — только пока экран
   на виду и слой мал; таймеры и GPS-режимы обосновываются в комментарии.
9. **Файл — одна ответственность**, ориентир ≤400 строк. Секции больших
   экранов выносятся в отдельные вью-файлы фичи.
10. **Тесты обязательны** для чистых функций и для каждого бага из прода
    (характеризационный тест до фикса).
11. **Тяжёлая работа вне main — только `@concurrent`.** Проект собирается с
    `NonisolatedNonsendingByDefault`: обычный `nonisolated async` исполняется
    на акторе вызывающего, то есть `Task { await Self.heavy() }` из MainActor
    остаётся на главном потоке. Утилиты без состояния (`Log`, `JSONFile`) —
    `nonisolated enum`, иначе вызов из `@concurrent` прыгает обратно на main.
12. **Фоновая задача, применяющая результат к состоянию, сверяется с
    поколением** (`generation`-токен): пока считали — состояние могли
    сбросить/заменить (пример: перестроение маршрута в `RouteService`).
13. **Пер-тиковые свойства читаются только из вью-изоляторов.** Свойства,
    которые LocationService/RouteService обновляют каждый GPS-тик (скорость,
    дистанции, `locationTick`, `nextStepDistance`), нельзя читать в body
    крупных экранов — любое такое чтение пересобирает весь экран ежесекундно
    (это был главный лаг карты). Читать их можно только в маленькой дочерней
    вью, чья единственная работа — показать это значение (примеры:
    `OverspeedVignetteGate`, `ManeuverBannerGate`, `LiveTripCard`,
    `LocationFollowDriver`). Сервис, в свою очередь, не перезаписывает
    @Observable-свойство тем же значением (см. `nearestCamera`).

## Карта модулей

| Папка | Что там |
|---|---|
| `App/` | Композиционный корень, настройки, корневая вью |
| `Features/<Фича>/` | Экраны и их состояния (`MapState`, шиты, секции) |
| `Models/` | Домен: поездки, камеры, рейтинг, штрафы |
| `Services/` | GPS, алерты, маршруты, лимиты, синк, сеть |
| `DesignSystem/` | Тема, переиспользуемые компоненты |
| `Support/` | `AppConfig`, `Log`, `Storage`, `APIClient`, форматирование |
| `CarPlay/` | Сцена CarPlay (переиспользует те же модели) |

## Тестирование

- Юнит-тесты — на чистые функции (`RadarMapTests`). MainActor-классы в
  тестах не инстанцируются (деаллокация в тест-рантайме крашится) —
  логика, которую надо тестировать, выносится в `nonisolated static`.
- Скриншот-смоук — DEBUG-аргументы запуска (`-showStats`, `-openFirstTrip`,
  `-carplayPreview`, …) + `simctl io screenshot`.
