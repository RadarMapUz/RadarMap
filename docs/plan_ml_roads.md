# План: «прокачать» ML карты дорог

Написан 05.10.2026. Владелец: «не только эта улица — везде такое, ML у нас
не такой мощный». Честный разбор и план.

## 0. Что есть сейчас и почему этого мало

- «ML» сейчас — голосование соседних участков (`lane_inference.py`): 96,6 %
  на спрятанных тегах, но только число полос и только там, где у улицы есть
  размеченные куски.
- Большинство дефектов на снимках владельца — не про ML, а про ГЕОМЕТРИЮ:
  положение зебры/стоп-линии/стрелок, конец разделительной, площадь узла,
  нити кромок. Правила ставят элементы независимо, и мы ловим их по одному
  скриншоту. Нейросеть поверх неверной геометрии этого не исправит.
- Нет МЕТРИКИ качества по стране: «стало лучше» видно только глазами на
  десятке мест.

Значит, прокачка — три направления: метрика → геометрия → ML там, где он
сильнее правил.

## 1. Метрика качества по всей стране (сначала, 2–3 дня)

Без неё любая «прокачка» — на ощупь.

1. **Эталон из самого OSM.** В Ташкенте 579 полигонов `area:highway` —
   нарисованные людьми контуры проезжей части. Это готовая разметка:
   считаем IoU нашего полотна с ними и ошибку ширины в метрах. Число на всю
   сеть, а не впечатление.
2. **Проверки порядка элементов** на каждом подходе (чистые, быстрые, по всей
   стране): стрелки после стоп-линии, пунктир в узле или на зебре,
   разделительная в узле или на дороге, полоса уже 1 м, зубец у кромки.
   Результат — число нарушений каждого класса на 1000 перекрёстков.
3. **Визуальный контролёр** (`road_review.py`): 200 случайных перекрёстков
   страны каждую сборку; разбор по 9 классам делаю я в сессии Claude Code
   (план Max, без API-кредитов) или модель через API при пополненном счёте.
4. Публикация останавливается, если любая метрика ухудшилась (как ворота по
   объёму).

Готово, когда: у каждой сборки есть таблица метрик, и её видно в `/status`.

## 2. Геометрия по одной модели (4–6 дней) — главный источник дефектов

Подробно — `docs/plan_roads_realistic.md`:
- модель «устья» подхода: зебра → стоп-линия → стрелки → сплошная → пунктир
  от одной линии, одинаково на всех подходах;
- площадь узла — между устьями, со скруглениями;
- одно полотно вместо слоёв лент (кромка только по внешнему краю — уходят нити);
- пилот osm2streets на 30 перекрёстках, лучшее — в сборку.

Метрики раздела 1 показывают эффект на всей стране, а не на одном снимке.

## 3. Настоящая модель для недостающих данных (1–2 недели)

Вместо голосования — обученная модель (градиентный бустинг, позже —
графовая нейросеть по сети дорог):

| Что предсказывает | Учится на | Зачем |
|---|---|---|
| число полос | все размеченные `lanes` Узбекистана + Казахстана, Кыргызстана, России (сотни тысяч участков) | пунктир везде, а не на 40 % |
| ширина полотна | `width` и `area:highway` | реальная ширина, не «по классу» |
| есть ли разделительная, какой ширины | пары встречных лент с газоном/без | разделительные там, где они есть |
| стрелки `turn:lanes` у подхода | размеченные подходы со светофором | стрелки на всех регулируемых подходах |
| где зебра у регулируемого подхода | `crossing=traffic_signals` | зебры на всех подходах |

Признаки — из графа: класс, направление, длина, кривизна, атрибуты соседей и
продолжений, степень узла, светофоры, плотность застройки, `maxspeed`.
Проверка — на спрятанных тегах по регионам (не по соседним кускам, чтобы не
подглядывать). В сборку идёт только то, что уверенно, с порогом под точность
≥ 95 %. Сплошная и всё, что про ПДД, — только по подтверждённым тегам.

Обучение — на маке, модель — файл весов в репо; сервер только применяет
(stdlib), обучение не нужно в рантайме.

## 5. Порядок

1. Метрика (раздел 1) — чтобы мерить всё дальнейшее.
2. Геометрия по одной модели (раздел 2) — главные дефекты «везде».
3. Обученная модель (раздел 3) — заполнение недостающих данных.
4. Каждая сборка: метрики ↑, иначе не публикуем.
