# Полосы на перекрёстках: как подключить данные (руководство владельца, 21.10.2026)

Цель — подсказка ряда («Из двух левых рядов», ряд стрелок в карточке манёвра) на любом
перекрёстке, а не только там, где в OSM есть `turn:lanes` (сейчас — у 1 из 26 левых
поворотов Ташкента). Всё подготовлено так, чтобы подключение источника было «положить
данные → одна команда». Формат данных — `docs/lanes_overlay_contract.md` (версия 1), он
главнее этого текста.

## 1. Что уже готово

| Что | Где | Зачем |
|---|---|---|
| Контракт данных | `docs/lanes_overlay_contract.md`, образец `server/fixtures/lanes_overlay_sample.json` | один формат для сервера и телефона |
| Телефон | `LaneOverlay` / `LaneOverlayService` (строится по контракту), рубильник пульта `features.laneOverlay` | берёт полосы из слоя там, где OSRM молчит |
| Сборщик | `server/build_lane_overlay.py` | CSV / GeoJSON / turn:lanes OSM → проверка → `lanes.<sha16>.json` + индекс |
| Публикация | `server/publish_lanes.sh` | сборка здесь, подпись ключом владельца, выкладка, уборка |
| Очередь разметки | `server/lanes_gaps.py` | какие подходы размечать первыми (по пробкам и/или маршрутам) |
| Шаблон обхода | `server/lanes/lanes_template.csv` | столбцы и три строки-образца |
| nginx | блоки `/radarmap/lanes/` в `server/nginx-radarmap-location.conf` | индекс без кэша, данные навсегда; ставится руками (п. 5) |
| Тесты | `server/test_build_lane_overlay.py`, `server/test_lanes_gaps.py` | контракт, каждый дефект, детерминизм, `--check` без ключа, приватность очереди |

Как телефон выбирает ряд перед манёвром: полосы OSRM → запись слоя (в 25 м от точки
манёвра, курс въезда в пределах её `tolerance`) → край по ПДД (20.2: налево — левый ряд,
разворот — крайний левый, направо — правый). Нет файла, битая подпись или sha — слоя нет,
всё работает как раньше.

## 2. Откуда взять данные — три пути

### А. Разметить `turn:lanes` в OSM (бесплатно, данные остаются у всех)

**Как это доезжает до телефона — честно.** У OSRM полосы появятся только после
пересборки его графа, а она на VPS **выключена с 19.07.2026** (граф не влезает в 2 ГБ
памяти; граф маршрутов — на выгрузке 15 июля, в плане `docs/plan_vps.md` — «граф OSRM с
мака»). Поэтому сам по себе путь через OSRM сейчас не работает. Работает путь через наш
слой: недельный экстракт (`update_roads.sh`, воскресенье 04:17) несёт теги как есть, и

```
bash server/publish_lanes.sh --osm
```

превращает `turn:lanes` в подходы `src=osm` и публикует их. Приложение не меняется. Когда
пересборка OSRM вернётся, те же полосы придут и от OSRM — они главнее слоя, конфликта нет.
Стрелки на асфальте карты (тайлы) подтягиваются недельной сборкой дорог и без этого.

**Правила разметки** (редактор iD или JOSM; подложка только **Bing** или **Esri** — снимки
Google и Яндекса обводить запрещено их условиями):

1. Линия (way) подхода должна **кончаться в узле перекрёстка**. Проходит сквозь
   перекрёсток — разрезать её в этом узле (ножницы в iD). Кончается раньше, на стоп-линии,
   и дальше идёт одним куском до перекрёстка — наш слой такой подход пропустит (OSRM
   дотянул бы, мы — нет, чтобы не угадывать).
2. Полосы — **слева направо по ходу движения**, через `|`; несколько стрелок одной полосы —
   через `;`. Число полос в `turn:lanes` = значению `lanes` в этом направлении.
3. Односторонняя проезжая часть (в том числе половинка разделённого проспекта) —
   `turn:lanes`:
   ```
   oneway=yes
   lanes=4
   turn:lanes=left|left;through|through|through;right
   ```
4. Двусторонняя — отдельно по направлениям (голый `turn:lanes` на двусторонней наш слой
   пропускает как неоднозначный):
   ```
   lanes=4
   lanes:forward=2
   lanes:backward=2
   turn:lanes:forward=left;through|through;right
   turn:lanes:backward=left|through;right
   ```
   `forward` — по направлению рисования линии (стрелка на линии в iD).
5. Значения: `left`, `slight_left`, `sharp_left`, `through`, `right`, `slight_right`,
   `sharp_right`, `reverse` (разворот), `merge_to_left`, `merge_to_right`, `none` или пусто
   (полоса без стрелки). Больше 8 полос слой не берёт.
6. Комментарий к правке: «turn:lanes по снимкам Bing». Ссылки «открыть в редакторе» —
   в очереди `lanes_gaps.py` (п. 6), столбец `edit_url`.

Что `--osm` пропускает и почему, печатается при каждом прогоне («пропущено: … — N»).

### Б. Свой слой

#### Обход (CSV)

```
cp server/lanes/lanes_template.csv server/lanes/lanes.csv
```

Удалите строки `example-*` (сборщик их не пропустит — образец не должен уехать на
телефоны) и заполняйте по строке на **подход** (одно направление въезда в перекрёсток):

| Столбец | Что писать |
|---|---|
| `id` | устойчивый идентификатор: `tash-0001`, `gap-1a2b3c4d` из очереди; латиница, цифры, `. _ : -`, до 64 знаков. Не меняйте его при правках — по нему видно историю |
| `lat`, `lon` | точка стоп-линии или узла перекрёстка (в 10 м от него — телефон ищет в 25 м от точки манёвра) |
| `bearing` | куда **едет** машина, въезжая в перекрёсток: 0 — на север, 90 — на восток, 180 — на юг, 270 — на запад. В очереди `lanes_gaps.py` уже посчитан |
| `tolerance` | допуск курса, по умолчанию 30 (пусто = 30), от 5 до 45. Меньше — на косых перекрёстках с близкими подходами |
| `lanes` | полосы слева направо, как их видит водитель: `left|left;straight|straight|straight;right`. Можно и в записи OSM (`through`, `reverse`, `slight_left`) — приведётся к словарю |
| `src` | `survey` (обход), `dashcam`, `vendor`, `osm` |
| `checked` | дата, когда видели на месте: `2026-10-21` |

Лишние столбцы можно (`note` — для себя, `confidence` — для регистратора); на телефон
они не попадают. Excel с русской локалью (разделитель `;`, десятичная запятая) читается
как есть. Строка с `#` в начале — комментарий.

Панель модератора: «Конструктор → Направления полос» рисует стрелки на асфальте в тайлах,
но в слой полос **не попадает** — у такой правки нет курса въезда. Карта панели удобна,
чтобы найти точку; строку пишите в CSV.

#### Видеорегистратор (ML)

Выход распознавания — тот же контракт, `src=dashcam`. Что модель обязана выдать **на
подход** (CSV по шаблону или GeoJSON, по Feature на строку — `.geojsonl`):

```
{"type": "Feature", "geometry": {"type": "Point", "coordinates": [69.27951, 41.31102]},
 "properties": {"id": "dc-41.31102-69.27951-352", "bearing": 352,
                "lanes": ["left", "left;through", "through", "through;right"],
                "src": "dashcam", "checked": "2026-10-20", "confidence": 0.91}}
```

- **точка** — стоп-линия / узел перекрёстка, привязанная к графу дорог, а не место, где
  стояла камера;
- **bearing** — курс машины на въезде (по треку, а не по компасу телефона);
- **lanes** — слева направо, стрелки по разметке и знакам 5.15.1/5.15.2; где стрелки на
  полосе нет — `none`, но не угадывать;
- **confidence** 0..1 — уверенность во **всём ряду** (число полос и стрелки вместе);
  неуверенно в числе полос — строку не выдавать вовсе;
- **checked** — дата съёмки; `id` — устойчивый (тот же подход в следующем проезде — тот же id).

В слой идут только строки не ниже порога:

```
python3 server/build_lane_overlay.py server/lanes/dashcam.geojsonl --min-confidence 0.8 --report
bash server/publish_lanes.sh --input server/lanes/lanes.csv --input server/lanes/dashcam.geojsonl --min-confidence 0.8
```

Ниже порога — «отброшено по правилам слияния» в отчёте, не ошибка; строка `dashcam` без
`confidence` при заданном пороге — ошибка. Хорошо бы требовать от модели двух согласных
проездов. В выход не должны попадать кадры, номера, лица — только поля контракта.

### В. Коммерческий набор (`src=vendor`)

Перед покупкой — по лицензии, письменно:
- разрешены производная работа и раздача её пользователям приложения (в нашем формате),
  хранение на телефоне без сети и коммерческое приложение;
- что с уже раздаными данными, когда лицензия кончится (наш ответ — пульт
  `features.laneOverlay=false` и публикация без строк `vendor`);
- требования к указанию источника — добавить в «Настройки → Источники данных» и
  `server/ATTRIBUTION.md`;
- смешение с OSM: ODbL требует открывать «производную базу» — если набор нельзя
  открывать, держите его строки отдельно от подходов `src=osm` (сборщик и так не
  смешивает записи: на одном подходе OSM уступает записи `vendor`, а не сливается с ней).

**Никогда — Яндекс и Google** (ни данные, ни снимки для обводки: их условия это
запрещают, и это правило проекта). Конвертер набора — в CSV или GeoJSON по шаблону;
файл набора в git не кладём, если лицензия этого не разрешает.

## 3. Пошагово: от данных до телефона

```
# 1. Данные — в server/lanes/lanes.csv (и/или свои файлы)

# 2. Проверка и отчёт: счёт по источникам, все отказы с файлом и строкой
python3 server/build_lane_overlay.py server/lanes/lanes.csv --report \
    --review /tmp/lanes_review.geojson

# 3. Глазами: /tmp/lanes_review.geojson на geojson.io — у каждого подхода линия
#    длиной 40 м ВХОДИТ в точку по курсу въезда; торчит не туда — ошибка bearing

# 4. Ворота без ключа и без сети (то же, что перед подписью)
bash server/publish_lanes.sh --check
bash server/publish_lanes.sh --check --osm-input ~/radarmap/roads.geojsonl   # если экстракт есть у себя

# 5. Подписать, не выкладывая; затем выложить
bash server/publish_lanes.sh --dry-run
bash server/publish_lanes.sh            # или с --osm: + подходы из turn:lanes экстракта на VPS

# 6. lanes.csv — в git (обход — наши данные; набор vendor — по лицензии)
git add server/lanes/lanes.csv && git commit -m "Полосы: …"
```

Любой дефект — отказ всей сборки со списком строк («НЕ ПОДПИСЫВАТЬ: …»): неизвестная
стрелка, 0 или больше 8 полос, точка вне Узбекистана, курс вне 0–359, допуск больше 45,
повтор `id`, два подхода ближе 15 м с курсами ближе 20°, дата из будущего. Исключение —
подходы `src=osm`: рядом с ручной записью OSM уступает ей, два подхода OSM в одном месте
выбрасываются оба (недельная выгрузка не должна останавливать публикацию из-за причуды
разметки), — это видно в отчёте.

Порядок публикации — как у лимитов и графа трасс: файл данных первым (через `.tmp`, рядом
`.gz`), проверка `sha256sum` на сервере, подписанный индекс последним, уборка
`lanes/` до текущего и предыдущего набора.

## 4. Проверить

На сервере (с любой машины):

```
curl -s https://soulmed.uz/radarmap/lanes/lanes_index.json \
  | python3 -c 'import base64,json,sys; print(base64.b64decode(json.load(sys.stdin)["payload"]).decode())'
# → {"files":[{"bytes":…,"format":1,"name":"lanes.<sha16>.json","sha256":"…"}],"format":1,"version":…}
curl -s -o /tmp/lanes.json https://soulmed.uz/radarmap/lanes/lanes.<sha16>.json && shasum -a 256 /tmp/lanes.json
# sha обязан совпасть с индексом
python3 server/build_lane_overlay.py /tmp/lanes.json --report     # тот же файл — те же подходы
```

На телефоне: Console.app, подсистема `uz.radarmap.ios`, поиск «полос» — строка о принятой
версии слоя. Точный текст задаёт `LaneOverlayService`; у графа трасс, по образцу которого
он строится, это «граф трасс: версия N», а отказ — «индекс сервера не прошёл проверку — не
применяем» (битая подпись) или «файл не сошёлся с индексом» (sha). Затем
маршрут через перекрёсток из слоя, где OSRM полос не даёт: в карточке манёвра должен быть
ряд стрелок с подсвеченными нужными полосами (раньше — только строка «левый ряд»). Телефон
проверяет индекс по своему расписанию; свежая установка берёт слой сразу.

## 5. nginx (руками, один раз)

Блоки `location /radarmap/lanes/` (данные: кэш на год — имя от содержимого) и
`location = /radarmap/lanes/lanes_index.json` (`no-cache` — откат доезжает сразу) — в
`server/nginx-radarmap-location.conf`. Без них всё работает через общий `/radarmap/` с
кэшем 5 минут, так что ставить можно и после первой публикации:

```
scp server/nginx-radarmap-location.conf root@45.130.148.94:/etc/nginx/snippets/radarmap-location.conf
ssh root@45.130.148.94 'nginx -t && systemctl reload nginx'
```

До установки `server/drift.sh` показывает этот файл как расхождение репо и сервера — это
ожидаемо.

## 6. Что размечать первым — `lanes_gaps.py`

Очередь подходов, через которые ездят чаще всего и где полос нет ни у OSRM, ни в слое, ни
(с `--osm`) в OSM. Запускать **на VPS** — там `traffic.db`; оттуда забирается только CSV
(база с машины не уходит: в ней минутные куски следа):

```
scp server/lanes_gaps.py server/build_lane_overlay.py root@45.130.148.94:/opt/radarmap/api/
scp server/lanes/lanes.csv root@45.130.148.94:/opt/radarmap/work/lanes.csv
ssh root@45.130.148.94 'cd /opt/radarmap/api && python3 lanes_gaps.py \
    --traffic-db /opt/radarmap/api/traffic.db \
    --overlay /opt/radarmap/work/lanes.csv \
    --osm /opt/radarmap/work/roads.geojsonl \
    --top 200 --csv /opt/radarmap/work/lanes_queue.csv --geojson /opt/radarmap/work/lanes_queue.geojson'
scp root@45.130.148.94:/opt/radarmap/work/lanes_queue.csv root@45.130.148.94:/opt/radarmap/work/lanes_queue.geojson .
```

(`lanes_gaps.py` берёт старение профиля из `traffic_build.py`, который лежит там же.)

Пока пробок мало — по списку маршрутов (ответы нашего OSRM с `steps=true`):

```
curl -s 'https://soulmed.uz/radarmap/osrm/route/v1/driving/69.2401,41.2995;69.2795,41.3110?steps=true&overview=false' -o route01.json
python3 server/lanes_gaps.py --routes route*.json --overlay server/lanes/lanes.csv --csv /tmp/lanes_queue.csv
```

Оба входа можно вместе: повороты маршрутов садятся на подходы пробок (столбец `routes`).

Выход — CSV в столбцах шаблона плюс справка: `traffic` (эффективные куски за месяцы,
со старением), `routes` (сколько маршрутов поворачивают здесь), `turns` (в сколько сторон
реально разъезжаются), `osm_turn_lanes` (`нет` — проверено по экстракту, `?` — экстракт не
дан), `edit_url` (iD на этом месте). Работа: взять верх очереди → на месте или по снимкам
заполнить `lanes`, `src`, `checked` → перенести строки в `server/lanes/lanes.csv` (лишние
столбцы не мешают) — или разметить в OSM по `edit_url` и публиковать с `--osm`.
Неразмеченная строка (пустой `lanes`) публикацию остановит — очередь не уедет на телефоны по
ошибке. «Есть в turn:lanes OSM, нет в слое: N» в сводке — значит, пора `publish_lanes.sh --osm`.

Подход в очереди — ребро OSM, после которого водители разъезжаются хотя бы в две стороны
(каждая — не меньше порога и 5 % потока подхода): подворотня проспекта перекрёстком не
считается. На старой базе (до выкладки `traffic_build` 8.8.16) скрипт честно предупреждает:
нет `pieces` — считает по отрезкам, нет `traffic_shared` — проверки «не один человек» нет,
остаётся только порог.

## 7. Откат

- **Сразу, без данных:** пульт —
  `bash server/publish_config.sh '{"features": {"laneOverlay": false}}'`
  (телефон вернётся к краю по ПДД; включить обратно — `--reset` или `true`).
- **Прошлые данные:** сборка детерминирована — тот же вход даёт те же байты и то же имя
  файла, а версия индекса (unix-время сборки) всё равно новая, поэтому откат — это
  обычная публикация прошлого входа:
  ```
  git show <коммит>:server/lanes/lanes.csv > /tmp/lanes_prev.csv
  bash server/publish_lanes.sh --input /tmp/lanes_prev.csv
  ```
  Если в прошлом наборе были подходы OSM (экстракт с тех пор сменился) — взять прошлый
  опубликованный файл: на сервере лежат текущий и предыдущий (`ssh root@45.130.148.94 ls
  /opt/radarmap/www/lanes/`; имя есть и в выводе прошлой публикации, строка «набор:»):
  ```
  curl -s -o /tmp/lanes_prev.json https://soulmed.uz/radarmap/lanes/lanes.<sha16>.json
  bash server/publish_lanes.sh --input /tmp/lanes_prev.json
  ```

## 8. Приватность

- В слое — только факты о дороге: точка перекрёстка, курс, полосы, источник, дата
  проверки. Ни устройств, ни поездок, ни людей. Столбец `note` на телефон не едет, но
  живёт в git — ничего личного туда не писать.
- Очередь `lanes_gaps.py` — узлы дорог, курс и счёт кусков, сложенный за месяцы: ни часа,
  ни дня, ни устройства, ни отдельного куска (это проверяет тест). Ребро попадает в очередь,
  только если его прошли не меньше `--min-traffic` (по умолчанию 10, ниже 2 нельзя)
  эффективных кусков **и** двое вместе за последние 5 недель (`traffic_shared`): улица
  одного водителя в очередь не попадает. Маршруты для `--routes` берите общие (не свою
  дорогу на работу — её повороты окажутся в CSV).
- Регистратор: в слой — только поля контракта; кадры, номера и лица из распознавания
  дальше машины разработчика не уходят.

## 9. Справка: пределы и решения сервера

| | Контракт | Сервер (`build_lane_overlay.py`) |
