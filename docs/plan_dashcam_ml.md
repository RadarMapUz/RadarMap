# План: «Разбор видео» — регистратор + трек → ML → правки карты

Цель: владелец загружает видео регистратора BYD и трек поездки (GPX из
RadarMap), а на карте видно, что модель нашла и куда это ставить:
светофоры, знаки ограничения, переходы, стрелки полос. Человек
подтверждает — правка уходит в конструктор и дальше в карту/OSM.

Принципы, от которых не отступаем:

- **Только свои данные.** Видео владельца, его трек, наши тайлы. Снимки
  Яндекса/Google — не источник (см. tools/autotune, server/map_edits.py).
- **ML предлагает, человек решает.** Ни одна находка не попадает в карту
  без подтверждения — та же логика, что у магнита конструктора.
- **Видео не уходит с мака.** На сервер — только координаты, класс и
  уверенность; кадры с номерами машин и лицами остаются локально.
- **Каждая находка объяснима:** 2–3 кадра, где объект виден, расстояние,
  сколько поездок его подтвердили.

## 2. Архитектура

Всё тяжёлое — на маке (M3 Pro, нейроускоритель): видео десятки гигабайт,
VPS на 2 ГБ его не потянет, и номера машин не должны покидать машину.

```
SD-карта / папка с роликами ─┐
GPX из RadarMap ─────────────┤
                             ▼
tools/dashcam/  (локально, на маке)
  ├─ ingest.py      — роли­ки, время, связь с треком, SQLite-каталог
  ├─ dashcam-detect — Swift CLI: Vision (текст, лица) + CoreML (объекты)
  ├─ locate.py      — кадр → точка и курс; триангуляция объекта
  ├─ cluster.py     — объединение находок по поездкам, сверка с картой
  └─ ui/            — локальная страница http://127.0.0.1:8780 (stdlib)
                             │  только координаты, класс, уверенность
                             ▼
панель на VPS: /api/edits → черновики конструктора → сборка тайлов / OSM
```

Хранилище — `~/RadarMapBuild/dashcam/dashcam.db` (SQLite): ролики,
поездки, кадры, находки, кластеры, решения. Кадры не храним — только
время кадра в ролике; вырезку показываем на лету через ffmpeg.

## 3. Конвейер

### 3.1 Импорт
- Источник: вставленная карта (читаем FAT32 напрямую) или папка.
  Копируем только дневные поездки, которые ещё не разобраны.
- Поездка = подряд идущие ролики с разрывом ≤ 5 мин.
- GPX кладётся рядом (перетаскиванием); поездка ищется по пересечению
  времени.

### 3.2 Синхронизация времени (главный риск)
Часы регистратора могут уходить от часов телефона на секунды–минуты.
- Сдвиг ищем сами: скорость из кадра (OCR раз в секунду) против скорости
  трека — максимум взаимной корреляции. Остановки у светофоров дают
  резкие «ступеньки», сдвиг находится до секунды.
- Показываем качество синхронизации (корреляция, сдвиг). Плохая — поездка
  помечается и в разбор не идёт.

### 3.3 Где был кадр
- Подробный трек (раз в секунду) — интерполяция точки и курса по времени.
- Старая поездка (упрощённый трек без времени) — проезды камер как опорные
  точки «время ↔ место», между ними — путь по скорости из кадра вдоль
  формы трека. Точность хуже — находки таких поездок получают меньший вес.
- Кадр берём раз в ~5 м пути; на стоянке — один кадр.

### 3.4 Распознавание (поэтапно)
| Класс | Чем | Этап |
|---|---|---|
| Знак ограничения скорости (число) | Apple Vision: текст в красном круге | M2 |
| Светофор (+ табло отсчёта) | Create ML Object Detection | M2 |
| Знак «пешеходный переход», зебра | Create ML | M2 |
| Стоп-линия | Create ML | M4 |
| Стрелки на полосах, число полос | Create ML + сегментация разметки | M4 |

Обучающая выборка: ~300 кадров на первую модель, разметка — в том же UI
(рамка мышью). Модель — Create ML (Apple, без лицензионных ловушек).
Номера машин и лица: Vision находит и размывает на любой вырезке,
которая показывается или отправляется.

### 3.5 Где объект на карте
- Направление на объект: позиция по горизонтали в кадре + угол обзора
  объектива (калибруется один раз).
- Расстояние: по размеру рамки и известному размеру объекта (знак ~0,7 м,
  секция светофора ~0,3 м) — грубо.
- Точно — **триангуляция**: один объект виден в нескольких кадрах подряд,
  лучи из разных точек пересекаются → ±3–5 м.
- Посадка на дорогу тем же магнитом, что в конструкторе
  (`map_edits.snap`): светофор — к узлу, знак — к своей ленте по курсу.
- **Калибровка на камерах фиксации:** их координаты известны (наша база),
  регистратор их видит — это готовые «эталонные точки» для замера ошибки
  привязки.

### 3.6 Объединение и сверка с картой
- Находки одного класса ближе 10 м — один кластер.
- Уверенность кластера: сколько поездок видели, сколько кадров, средняя
  уверенность модели, качество синхронизации.
- Сверка с нашими тайлами:
  - **подтверждает** — такой объект в карте уже есть рядом;
  - **новое** — в карте нет;
  - **расходится** — в карте есть, но в другом месте или другой (60 вместо 70);
  - **возможно, нет** — проезжали днём ≥ 3 раз и ни разу не увидели.

## 4. Интерфейс

Одна страница, карта в центре — как конструктор в панели.

```
┌─────────────┬──────────────────────────────────────┬──────────────────┐
│ ПОЕЗДКИ     │                                      │ НАХОДКА          │
│             │           КАРТА (наш стиль)          │                  │
│ 07.10 08:05 │   трек поездки цветом скорости       │ [кадр 1][кадр 2] │
│ ✓ синхр. 1с │   ● новое   ● подтверждает           │ [кадр 3]         │
│ ✓ разобрано │   ● расходится  ○ низкая увер.       │ Светофор         │
│ 06.10 08:55 │                                      │ 3 поездки · 92 % │
│ ⟳ 64 %      │   выбранная находка: лучи от кадров  │ ±4 м · новое     │
│ 05.10 15:56 │   к точке, магнит к узлу             │                  │
│ ✗ нет GPX   │                                      │ [Принять] A      │
│             ├──────────────────────────────────────┤ [Отклонить] R    │
│ + Загрузить │ ▶ ВИДЕО ━━━━━━━●━━━━━━━━━━  08:32:21 │ [Сдвинуть] M     │
│   видео/GPX │   кадр синхронно с машинкой на карте │ [Не то] → класс  │
└─────────────┴──────────────────────────────────────┴──────────────────┘
 Фильтры: класс · уверенность ≥ 70 % · статус · только новое
```

- **Слева — поездки** со статусом: импорт → синхронизация (сдвиг,
  качество) → разбор (прогресс) → готово. «Загрузить» принимает ролики,
  папку, карту и GPX перетаскиванием.
- **Карта** — наш стиль (те же тайлы, что у приложения). Трек поездки;
  находки значками класса, цвет — статус сверки; кластеры с числом.
- **Внизу — видео** с ползунком: играет ролик, машинка едет по треку.
  Клик по точке трека — видео прыгает туда. Это главный инструмент
  проверки «модель не врёт».
- **Справа — находка**: 2–3 вырезки (номера и лица размыты), класс,
  уверенность, ±метры, сколько поездок, статус сверки. На карте — лучи
  от кадров к точке.
- **Решения**: Принять (A), Отклонить (R), Сдвинуть (M — тащить с
  магнитом), «Не то» (сменить класс). Стрелки ←/→ — следующая находка.
  Отклонённое помнится: модель больше не предлагает его на этом месте.
- **Пакетно**: «Принять всё подтверждённое ≥ 3 поездками и ≥ 90 %» —
  с предпросмотром списка, а не вслепую.
- **Разметка для обучения**: режим «рамка» — нарисовать объект на кадре,
  который модель пропустила; копится обучающая выборка.

## 5. Куда уходят решения

- Принятое → `POST /api/edits` панели как черновик конструктора с
  происхождением `dashcam:<поездка>` и уверенностью; в панели видно, что
  это из видео. Дальше обычный путь: сборка тайлов, публикация владельцем.
- Для OSM — выгрузка `.osc` (через `map_edits.as_osm`) и загрузка через
  JOSM с учётки владельца, по правилам организованной правки OSM.
- На сервер не уходит ни одного кадра.

## 6. Этапы

| Этап | Что | Оценка |
|---|---|---|
| **M1** | Импорт с карты, связь с GPX, синхронизация по скорости, страница: поездки + карта с треком + видео с ползунком (без ML) | 1–2 дня |
| **M2** | Знаки ограничения (Vision) и светофоры/переходы (Create ML, ~300 кадров разметки), привязка и триангуляция, карточка находки, Принять/Отклонить, выгрузка черновиков | 2–3 дня |
| **M3** | Объединение по поездкам, сверка с картой, пакетное принятие, калибровка по камерам фиксации | 1–2 дня |
| **M4** | Стоп-линии, стрелки полос, число полос | 3–5 дней |
| **M5** | Выгрузка в OSM, отчёт «сколько улиц покрыто видео», план съёмки «где ещё не ездили» | 1–2 дня |

## 7. Как поймём, что работает

- Синхронизация: сдвиг найден для ≥ 90 % дневных поездок, погрешность ≤ 1 с.
- Привязка: медианная ошибка на камерах фиксации ≤ 8 м.
- Модель: доля принятых человеком находок ≥ 80 % при пороге уверенности
  по умолчанию.
- Карта: число светофоров/знаков в центре Ташкента до/после, метрики
  `road_metrics.py` не хуже.

## 8. Риски

- Часы регистратора и телефона — решается синхронизацией по скорости.
- Пробки закрывают разметку — разметку берём только с кадров на ходу
  (> 15 км/ч), объекты над дорогой (светофоры, знаки) видно и в пробке.
- Солнце в объектив, ночь — только дневные поездки на первых этапах.
- Объём: 25 ч дневного видео ≈ 90 000 кадров с шагом 5 м — на M3 Pro
  это минуты на распознавание, узкое место — чтение с карты (~2 ГБ/мин).
