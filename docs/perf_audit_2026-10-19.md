**Вывод честно:** разница по CPU — в пределах разброса симулятора (два
прогона одной сборки расходятся на 15 %). Пакет А бьёт не по CPU главного
потока, а по пробуждениям: виджеты (48 → 1–2 в сутки), радио ссылки прибытия
(раз в минуту → по изменению), часы, сторож фризов вне экрана машины,
лишние записи @Observable. Это Time Profiler не видит — нужен замер батареи
на телефоне (👤, этап 2.7) и MetricKit по версиям.

`applyHiddenLayers` ушёл из верхних строк (было 7 мс за 40 с).

**Что на самом деле стоит на main из кода приложения** (оба варианта):
`EngineMapView.Coordinator.layoutPositionView` + `EngineNativeMapView.layoutSubviews`
— 150–215 мс за 40 с (≈ 0,5 % ядра): перепроекция стрелки «я» на каждом шаге
глайда. Следующий кандидат — пункт 2.21 плана.
