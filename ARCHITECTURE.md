# Архитектура RadarMap

Паттерн — **MV (Model–View)**, родной для SwiftUI: без ViewModel-прослоек,
вьюхи читают наблюдаемые модели напрямую. Документ фиксирует правила,
по которым пишется и ревьюится код.

## Слои

```
View (SwiftUI)  →  @Observable модели/сервисы  →  чистые функции домена
      ↑                    ↑                              ↑
 только разметка   состояние + оркестрация      вся математика, тестируемая
 и локальный       (MainActor)                  (nonisolated static)
 UI-state
```

- **Композиционный корень** — `AppEnvironment` (`App/AppEnvironment.swift`):
  создаёт все сервисы один раз, связывает их и раздаёт через
  `.environment(...)`. Телефонная сцена и CarPlay делят один экземпляр
  (`AppEnvironment.shared`).
- **View** — только разметка, анимации и локальный UI-state
  (`@State` для флагов шитов, выбранных элементов). Никаких вычислений над
  доменными данными: группировки, агрегаты, фолбэки живут в моделях.
- **Модель/сервис** — `@MainActor @Observable final class`. Состояние
  `private(set)`, мутации через методы. Скрины-состояния экранов
  (например, `MapState`) — тоже модели, а не «ViewModel»: они не
  форматируют данные для вью, а владеют состоянием экрана.
- **Чистые функции** — `nonisolated static` (`DrivingScore`,
  `FineSchedule`, `TripStats.pruned/sanitized`, `LocationService.measuredSpeed`).
  Всё, что можно посчитать без ссылок на сервисы, пишется так — это
  единственный слой, который покрывается юнит-тестами напрямую.

## Правила

1. **Данные вниз, действия вверх.** Вью не пишет в чужое состояние —
   зовёт метод модели. Колбэки между сервисами — через слабые замыкания,
   выставленные в `AppEnvironment`.
2. **Протокол — только там, где нужна подмена** (репозиторий камер —
   `CameraRepository`). Не плодим протоколы «на всякий случай».
3. **Ошибки не глотаются.** Либо `Log.<подсистема>.error(...)`, либо
   комментарий, почему молчание — осознанное решение. Голых `try?` без
   одного из двух не бывает.
4. **Константы — в `AppConfig`** с комментарием, почему значение такое.
   Магические числа в коде запрещены.
5. **UserDefaults — только через `Storage`** (типизированные ключи).
   Исключение — `AppSettings`: настройки живут за собственным типизированным
   фасадом (`Keys` + `register(defaults:)`). Прямых строковых ключей в коде нет.
6. **Сеть — только через `APIClient`**: базовый URL, таймауты, проверка
   статуса, декодирование и лог в одном месте. Исключения — со своей
   причиной в коде: OSRM (`RouteService`, свой хост и разбор), тайлы карты
   (`EngineTileGuard` — сам `URLProtocol`, его сессия не должна проходить
   через него же; `TileReleaseStore` — эфемерная сессия без кэша под
   многомегабайтные корни выпуска).
7. **Локализация**: пользовательские строки — `LocalizedStringKey` или
   `String(localized:)`. Тернарники строковых литералов внутри `Text()`
   запрещены (обходят локализацию). Числа — по ЯЗЫКУ приложения, не по
   региону телефона: `Formatting.decimal` / `Shared/NumberFormat` (виджеты,
   плашка, часы); `String(format:)` без локали ставит точку в русском.
8. **Батарея — приоритет №1.** Повторяющиеся анимации — только пока экран
   на виду и слой мал; таймеры и GPS-режимы обосновываются в комментарии.
   Периодическая сеть — только через планировщик (`NetScheduler`/`SyncPlan`,
   36B): служба не заводит свой цикл опроса, а отдаёт `isDue` (по своим
   часам, без сети) и `syncTick`/загрузку — и едет в общем окне радио.
9. **Файл — одна ответственность**, ориентир ≤400 строк. Секции больших
   экранов выносятся в отдельные вью-файлы фичи.
10. **Тесты обязательны** для чистых функций и для каждого бага из прода
    (характеризационный тест до фикса).
11. **Тяжёлая работа вне main — только `@concurrent`.** Проект собирается с
    `NonisolatedNonsendingByDefault`: обычный `nonisolated async` исполняется
    на акторе вызывающего, то есть `Task { await Self.heavy() }` из MainActor
    остаётся на главном потоке. Утилиты без состояния (`Log`, `JSONFile`) —
    `nonisolated enum`, иначе вызов из `@concurrent` прыгает обратно на main.
    Короткий путь — `offMain { … }` (`Support/Concurrency.swift`): для работы
    в ответ на действие человека, приоритет вызывающего наследуется. Фоновой
    работе, которой нужен НИЗКИЙ приоритет (разбор файлов при запуске),
    оставлен `Task.detached(priority: .utility)` — offMain поднял бы её.
12. **Фоновая задача, применяющая результат к состоянию, сверяется с
    поколением** (`generation`-токен): пока считали — состояние могли
    сбросить/заменить (пример: перестроение маршрута в `RouteService`).
13. **Пер-тиковые свойства читаются только из вью-изоляторов.** Свойства,
    которые LocationService/RouteService обновляют каждый GPS-тик (скорость,
    дистанции, `locationTick`, `nextStepDistance`), нельзя читать в body
    крупных экранов — любое такое чтение пересобирает весь экран ежесекундно
    (это был главный лаг карты). Читать их можно только в маленькой дочерней
    вью, чья единственная работа — показать это значение (примеры:
    `OverspeedVignetteGate`, `ManeuverBannerGate`, `LiveTripCard`,
    `LocationFollowDriver`). Сервис, в свою очередь, не перезаписывает
    @Observable-свойство тем же значением (см. `nearestCamera`).
14. **Экран и его расшифровка читают ОДИН посчитанный объект.** Карточка и
    открывающийся с неё info-шит получают одну и ту же сводку — шит не считает
    своё (было: в шапке 85 «за неделю», по тапу 82 «за 30 дней»). Агрегатов
    с зашитым окном (30 дней, 7 дней) в приложении нет: считает
    `TripHistory.summary(days:history:period:anchor:)`, окно задаёт период.
    Цифра на экране всегда подписана своим окном, а пожизненные счётчики —
    отдельным блоком «За всё время».
15. **Периоды — календарные.** Скользящее окно («последние 7×86400 секунд»)
    меняет цифры само по себе, без новых данных; сравнение с прошлым периодом
    плавает вместе с часами. Окно берётся у `Calendar` и листается якорем.
    Сегмент, который не может показать то, что обещает названием (например,
    «Всё время» при чистке истории), в интерфейс не выносится.
    Окно — ПОЛУИНТЕРВАЛ `[начало, конец)`, и фильтр на весь проект один —
    `TripDayBook.days(_:in:)`. `Calendar` стыкует соседние окна секунда в
    секунду, `DateInterval.contains` включает ОБА конца, а день дневного
    агрегата — всегда ровно полночь: через `contains` первый день текущей
    недели проходил и фильтр прошлой, `previousDistance`/`previousRating`
    завышались, и дельта «стало лучше/хуже» врала на каждом переходе периода.
    Своего фильтра рядом не заводить — второй ответ на «в каком окне этот
    день» и был причиной.
16. **Долгоживущие цифры считаются по дневным агрегатам** (`TripDay`), а не по
    записям: записи чистятся (треки — 7 дней, записи — 30 дней / 50 шт), день
    весит десятки байт и живёт вечно. Запись, уходящая из истории «в оборот»
    (resume, удаление, разделение), обязана быть вычтена из агрегата
    (`TripDayBook.unfolded`) — иначе двойной счёт.

17. **Ретро-чистка истории никогда не пересобирает долгоживущее из
    короткоживущего.** `LifetimeStats.rebuilt(from:)` и `TripDayBook.rebuilt`
    законны ровно в одном случае — первичная миграция, когда агрегатов ещё
    нет. Чистка уже накопленного правит агрегаты ХИРУРГИЧЕСКИ (вычесть
    старое, прибавить новое): rebuild по обрезанной истории молча стирает
    годы. Дважды ловили на code review — оба раза чистка выглядела безобидно.

18. **Новое поле в персистентной Codable-структуре — только `Optional` или с
    декод-дефолтом.** `TripRecord`, `TripDay`, `TripStop`, `PassedCamera`,
    `InflightTrip`, `LifetimeStats`, `SavedPlace` лежат у пользователей на
    диске; синтезированный `init(from:)` значения-по-умолчанию НЕ применяет,
    и одно неопциональное поле валит декод всего файла — история
    превращается в пустую. Переименовывать и удалять поля нельзя тем более.

19. **Данные, применяемые без участия пользователя, — только за подписью и
    только fail closed.** База камер (`cameras.json`), пульт (`config.json`),
    правки модератора (`overrides.json`), лимиты скорости
    (`speed_limits_index.json` + sha файла), память о треногах, дорожные
    тайлы, граф трасс для маршрута без сети (`routes/route_graph_index.json`
    + sha файла) и слой полос (`lanes/lanes_index.json` + sha файла)
    применяются молча, поэтому проходят
    через один `SignedPayload<T>`: подпись Ed25519 проверяется ДО разбора JSON,
    и любая неисправность — нет подписи, чужой ключ, битый JSON, значение вне
    границ — означает работу на значениях сборки, а НЕ на присланных. Второй
    копии проверки быть не должно: это единственное, что отделяет наши данные
    от данных того, кто перехватит HTTP или получит доступ к серверу.

20. **Оповещения о камерах не управляются снаружи.** Пульт умеет погасить
    маршруты, краудсорс и метрики — всё, что и так живёт на сервере. Радиус,
    громкость и сам факт предупреждения он не трогает по построению: база
    лежит на телефоне, предупреждение обязано работать без сервера вовсе, а
    значит не должно зависеть и от того, что сервер пришлёт. Правки базы —
    единственное исключение, и именно поэтому у них отдельный предохранитель:
    файл, скрывающий и переносящий вместе больше `overrideMaxHiddenShare` базы
    (переносов — не больше `overrideMaxMovedShare`), отвергается целиком
    (`CameraOverrideEngine.isSane`). События дороги (перекрытие, ремонт),
    метан на АГНКС и пробки — тоже не камеры: свой список, свой слой под
    камерами, голос — ниже камеры и с запасом до её радиуса.

21. **Системные XPC-вызовы — никогда на пути тика и алерта.** Перечисление
    голосов (`AVSpeechSynthesisVoice.speechVoices()`), списков устройств и
    прочие походы к системным демонам стоят сотни миллисекунд и блокируют
    главный актор непредсказуемо долго. Их результат кэшируется на процесс
    (`static let`) и прогревается вне main при старте сервиса. Урок сборки
    1.1.1: поиск узбекского голоса на каждую фразу замораживал спидометр и
    кнопки CarPlay ровно в момент оповещения — «в машине ничего не работает».

22. **Мишень пальца — 44 pt**, и не на глаз: `tapTarget()` из
    `DesignSystem/Components.swift`. Растёт только область касания — вид
    элемента остаётся своим. Правило появилось не из доступности: кнопки
    закрытия разъехались от 18 до 44 пунктов именно потому, что каждая
    задавала размер сама, а за рулём промах по крестику — это второй взгляд
    на экран вместо взгляда на дорогу.

23. **Новый вид данных от водителей — своим списком, если старая сборка
    может прочитать его как камеру.** Разбор отметок в выпущенных сборках
    читает незнакомый тип как «радар» — ремонт дороги в общем `/api/mobile`
    стал бы у них передвижным радаром со звуком. Поэтому перекрытия и ремонт
    живут в `GET /api/road`, метан — в `GET /api/cng`, а старые сборки их не
    запрашивают вовсе. Тот же вопрос — к любому новому полю или типу: что
    сделает с ним сборка, которая уже у людей.

## Карта модулей

| Папка | Что там |
|---|---|
| `App/` | Композиционный корень, настройки, корневая вью |
| `Features/<Фича>/` | Экраны и их состояния (`MapState`, шиты, секции) |
| `Models/` | Домен: поездки, камеры, рейтинг, штрафы |
| `Services/` | GPS, алерты, маршруты, лимиты, синк, сеть |
| `DesignSystem/` | Тема, переиспользуемые компоненты |
| `Support/` | `AppConfig`, `Log`, `Storage`, `APIClient`, форматирование |
| `CarPlay/` | Сцена CarPlay (переиспользует те же модели) |
| `Shared/` | Общее с виджетами и часами: снимки виджетов, плашка, кнопки плашки |
| `RadarMapWidgets/`, `RadarWatch/` | Виджеты и плашка; часы — только показывают и шлют «Радар!» |
| `server/` | API, админка, сборщики подписанных файлов, бот; ключ подписи — только у владельца |

## Тестирование

- Юнит-тесты — на чистые функции (`RadarMapTests`). MainActor-классы в
  тестах не инстанцируются (деаллокация в тест-рантайме крашится) —
  логика, которую надо тестировать, выносится в `nonisolated static`.
- Сценарные тесты (`ScenarioDriveTests` и соседи) гоняют реальную базу
  через фильтр фиксов, гейты и движок оповещений: город, трасса, тоннель,
  шумный GPS, полночь, обновление формата.
- Скриншот-смоук — DEBUG-аргументы запуска (`-showStats`, `-openFirstTrip`,
  `-carplayPreview`, …) + `simctl io screenshot`.
