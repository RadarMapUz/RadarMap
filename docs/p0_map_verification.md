# P0: плавность и управление MapLibre

Дата: 2026-09-11. Изменения клиентские; развёртывание на VPS не требуется.

## Реализовано

- Владение камерой переключается в свободный осмотр через нативный delegate
  MapLibre для всех жестов, включая double tap. Оно сохраняется после конца
  жеста и инерции до кнопки «К машине». Саму инерцию и отмену нативной анимации
  при жесте выполняет MapLibre; второй механизм движения поверх него не добавлен.
- Выбор камеры ждёт отказа double tap, чтобы первый тап не открывал карточку.
- Размер контейнера инвалидирует позицию слежения; в осмотре GPS не возвращает
  карту. Длительность слежения ограничена фактическим интервалом обновлений;
  Reduce Motion учитывается.
- Неизменившаяся позиция не публикуется. Point/line features создаются через
  native API, без сериализации и повторного разбора JSON.
- Идентичность MKPolyline определяет поколение маршрута. Накопленные расстояния
  кэшируются, срезы находят границы бинарным поиском. Подготовка выполняется
  через @concurrent, отмена и номер задания защищают от устаревшего результата.
- Камеры выбираются по видимой области с запасом 50%, максимум 160. Кэш
  инвалидируется при выходе из области и изменении версии базы/лимитов/настройки.
  Поиск лимитов больше не выполняется на каждом GPS-тике в SwiftUI body.
- День/ночь меняют цвета существующих слоёв; здания переключают visibility.
  Иконки кэшируются между загрузками стиля. Повторная загрузка после проверки
  подписанного индекса сохранена отдельно от смены оформления.

При проверке обнаружен и исправлен сбой Foundation CAST(hex, UIColor).
Цвета передаются как UIColor, match по классу — как условные выражения.

## Измерения

Instruments → Points of Interest, subsystem `uz.radarmap`, category
`MapPerformance`: Map apply, Route preparation, Route source, Follow camera,
Style replacement, Camera viewport query.

DEBUG дополнительно пишет количество кадров и p95 encoding/rendering в мс.
Буфер ограничен 300 кадрами и сбрасывается при idle. Эти значения движка
не равны полному времени кадра на экране и не доказывают 60 FPS.

## Проверки

- Сборка iOS Simulator: успешна.
- В симуляторе проверены: запуск тайлов и камер, double tap → свободный осмотр,
  новая GPS-точка (дистанция до камеры обновилась с 469 до 345 м без возврата
  вида), кнопка «К машине», появление домов, светлая → тёмная → светлая тема.
- После исправления цветов смена темы не вызывает исключений. Signpost-журнал
  процесса финальной сборки содержит две первоначальные замены стиля (старт,
  готовность подписанного индекса) и ни одной при двух переключениях темы.
- Pinch, rotation, инерция и длительная поездка отдельно не прогонялись:
  обработка использует общий нативный delegate, но ручная проверка этих
  сценариев ещё нужна.
- EngineMapStyleTests: 22 теста, все прошли. Включены срезы петли,
  пустая/завершённая геометрия, фоновая подготовка, границы кэша области
  и нативные цвета темы.
- Полный тестовый набор не запускался: в существующем TypeScaleTests есть
  обращения к отсутствующему API Theme. Для целевого запуска использован
  временный xcconfig, настройки проекта не менялись.
- Физический iPhone 16 Pro / iOS 27 обнаружен, но devicectl сообщает:
  `The developer disk image could not be mounted on this device`.
  Поэтому физические FPS/CPU/память/нагрев не измерены, исходная трасса
  до изменений не записана. Нужен совместимый комплект Xcode/device support.

Перед подтверждением бюджета производительности повторить сценарии плана
на физическом устройстве: pan/pinch/rotation/inertia, GPS с маршрутом,
тёплый/холодный кэш и плохая сеть. Загрузочные байты и отмены запросов пока
измерять сетевыми инструментами; собственные счётчики в tile guard не добавлены.
