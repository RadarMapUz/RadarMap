# План: разметка дорог по снимкам — ML + ручной инструмент

Написан 06.10.2026 по запросу владельца: «чтобы ML прошёлся по реальной карте
(снимок Google, Беруни × Малая кольцевая) и нарисовал бордюры, разделительные,
линии, знаки — без странных отступов; или вручную, если сам не может».

## 0. Главное ограничение — откуда снимок

Снимок, который прислан, — Google Maps. **С него нельзя ни обводить руками, ни
прогонять нейросеть**: условия Google (и Яндекса, 2ГИС, Bing, Esri — по нашим
же правилам проекта) запрещают извлекать из снимков данные для своей карты. Это
не формальность: карта — продукт в App Store, и претензия правообладателя
снимает его целиком. Поэтому весь план строится на законных снимках.

| Источник | Разрешение | Можно ли для своей карты | Цена |
|---|---|---|---|
| Google / Яндекс / 2ГИС | 10–30 см | **нет** | — |
| Bing, Esri World Imagery | 30–50 см | только для правок **в OSM** (через iD/JOSM), не для своей базы напрямую | бесплатно |
| Mapillary (фото с улиц) | — | да, CC BY-SA; знаки и разметка уже распознаны | бесплатно |
| Свой регистратор (телефон в машине) | — | да, полностью наше | время |
| Купленная съёмка (Maxar, Airbus Pléiades Neo, Planet SkySat) | 30–50 см | да, по лицензии на производные данные | ≈ $10–25 за км², Ташкент ≈ 400 км² |
| Госагентство кадастра / геопортал Узбекистана | 10–50 см | по договору | переговоры |

**Совет:** два законных пути, лучше оба.
1. **Через OSM** (бесплатно, сразу): обводим Ташкент по Bing/Esri **в OSM** —
   `area:highway`, `lanes`, `turn:lanes`, `width`, переходы, островки,
   разделительные. Наш конвейер уже всё это читает: исправление в OSM через
   неделю само приезжает на карту (и улучшает OSM для всех — это законно и
   приветствуется сообществом).
2. **Купить снимок Ташкента** с лицензией на производные данные — тогда ML
   может работать по нему напрямую и класть результат в нашу базу.

## 1. Что ML реально умеет по снимку 30 см (и чего нет)

Уверенно: кромка проезжей части, разделительная (газон/бетон), островки,
зебры, сплошные и пунктир, стоп-линии, стрелки (крупные).
Плохо: кромка под деревьями (Беруни — кроны закрывают пол-улицы), под
машинами в пробке, в тени домов; знаки сверху не видны вообще (знаки — только
Mapillary/регистратор).

Значит, ML даёт **предложение**, а не готовую карту: каждый перекрёсток
смотрит человек. «Нейросеть нарисует город сама» — нет; «нейросеть сделает
80 % работы, человек за 30 секунд поправит перекрёсток» — да.

## 2. Конвейер ML (по купленному снимку или для подсказок при правке OSM)

1. **Нарезка** снимка на тайлы 512×512 с привязкой.
2. **Сегментация** (обученная модель, на маке):
   - асфальт / газон / тротуар / разделительная — сегментация по пикселям
     (SegFormer или U-Net; старт — готовые веса SpaceNet/DeepGlobe, дообучение
     на 200–300 размеченных тайлах Ташкента);
   - разметка — отдельная тонкая маска (линии, зебры, стрелки);
   - SAM 2 — для точной кромки по одному клику в ручном режиме.
3. **Векторизация**: маска → контур (упрощение, сглаживание, прямые углы у
   бордюров) → линии разметки → привязка к нашим лентам (`roads`): каждая
   кромка знает свою ленту, каждая зебра — свой подход.
4. **Проверка на согласованность** (то, что убирает «странные отступы»):
   ширина полотна = сумма полос × 3–3,75 м; кромки параллельны оси; зебра
   поперёк; островок не уже 1,5 м. Нарушение — в очередь человеку.
5. **Очередь модерации** в нашей админке: перекрёсток, снимок под ним, слой
   предложения, кнопки «принять / поправить / отклонить».
6. **Сборка** берёт принятое как ручные правки (`edits.json`, флаг
   `FLAG_HAND_DRAWN` уже есть) — поверх OSM и с приоритетом над эвристикой.
7. **Метрики** (`road_metrics.py`): доля перекрёстков с принятой геометрией,
   расхождение кромки с эталоном в метрах.

Срок: 3–4 недели до первых 100 перекрёстков; обучение — на маке (GPU M-серии
хватает), сервер только применяет.

## 3. Ручной инструмент (нужен в любом случае)

Конструктор в админке уже двигает камеры и правит дороги; расширяем его до
редактора перекрёстка:

| Инструмент | Что делает |
|---|---|
| Кромка | обвести полотно 4–6 кликами; углы скругляются сами |
| Разделительная / островок | контур или «полоса шириной N м» вдоль ленты |
| Полосы | число полос и `turn:lanes` по подходу — стрелки встанут сами |
| Зебра | один клик на подходе — встаёт поперёк, в ширину полотна |
| Стоп-линия | клик — поперёк своей полосы, перед зеброй |
| Знак | точка + тип из справочника ПДД (для озвучки и иконки) |
| Шаблон перекрёстка | «крест 4×4 со светофором», «Т с карманом» — заполняет всё, человек поправляет |

Подложка в редакторе — только законная (наша карта; Bing/Esri — лишь при
правке **в OSM**; купленный снимок — если купим). Сохранение — в `edits.json`
с автором и датой; публикация — как сейчас, подписью владельца.

Срок: 1–1,5 недели на редактор.

## 4. Что советую

1. **Сейчас (бесплатно, законно):** ручной редактор (раздел 3) + обводка
   главных 50–100 перекрёстков Ташкента в OSM по Bing/Esri. Это быстрее всего
   даёт «как у Яндекса» там, где ездят больше всего.
2. **Параллельно:** Mapillary — проверить покрытие Ташкента; если есть —
   знаки и стрелки из уже распознанных объектов.
3. **Когда будет бюджет:** купить снимок Ташкента (≈ $4–10 тыс.) с лицензией
   на производные данные и запустить ML-конвейер (раздел 2) — он масштабирует
   работу на весь город и областные центры.
4. **Не делать:** обводить или прогонять ML по Google/Яндексу — даже «только
   для себя». Это риск для всего приложения.

Пока идёт это — продолжается правка правил сборки (`docs/plan_junctions_polish.md`):
она улучшает все перекрёстки страны разом, а снимки — точечно лучшие.
