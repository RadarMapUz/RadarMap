# План: реалистичный перекрёсток

Написан 05.10.2026 по снимку владельца (Каратош × Бешёгоч): элементы есть, но
стоят вразнобой.

## Что не так (снимок)

1. Стрелки полос — после стоп-линии, между ней и зеброй; значки комбинированных
   стрелок похожи на «Н».
2. Стоп-линия в 15–20 м от зебры (в жизни 1–3 м).
3. Разделительная проходит через весь перекрёсток.
4. Пунктир заходит в перекрёсток.
5. Площадь перекрёстка — клякса, по которой плавает зебра.
6. Жёлтые «нитки» внутри асфальта, где рядом две ленты.

## Причина

Каждый элемент ставится своим правилом по своей точке OSM: стоп-линия — по
светофору, зебра — по переходу, стрелки — по тегу полос, площадь узла — по
графу. Они друг о друге не знают. Чинить по одному элементу бесполезно —
нужна единая модель подхода.

## Шаги

### 1. Модель «устья» перекрёстка — 2–3 дня
Для каждого подхода — одна линия устья: где подход встречает кромку
пересекающей улицы. От неё против движения, по оси подхода:

| от устья | элемент |
|---|---|
| 0–4 м | зебра |
| 5 м | стоп-линия |
| 10–20 м | стрелки полос |
| до 30 м | сплошная разделительная полос |
| дальше | пунктир |

Разделительная кончается носом у зебры. Площадь перекрёстка — многоугольник
между устьями всех подходов со скруглёнными углами. Если в OSM есть переход или
стоп-линия в пределах 10 м от расчётного места — берётся их положение, и
остальное выстраивается от него, порядок не ломается.

Модуль `junction_model.py`, чистый, с тестами на порядок элементов.

### 2. Пилот osm2streets — 1–2 дня, параллельно
Открытый движок (Apache 2.0) строит ту же модель из OSM. 30 перекрёстков: наш /
osm2streets / Яндекс рядом; где он лучше — берём его геометрию узлов.

### 3. Одно полотно вместо слоёв лент — 1–2 дня
Ленты, кромки и площади узлов — единый контур; кромка — только по внешнему
краю. Уходят жёлтые нитки и зубцы.

### 4. Значки — полдня
Стрелки как у Яндекса: простые белые, «прямо и направо» — одним значком.

### 5. Приёмка
20 эталонных перекрёстков (Беруни, Рашидов, Каратош, Мукими…), снимки у нас и
у Яндекса рядом. `road_review.py` проверяет порядок элементов каждого подхода:
стрелки после стоп-линии, разделительная в узле, пунктир в узле — брак.

Срок: 1–1,5 недели.
