# План: один голос вместо двух, режимы и узбекский

Составлен 7 августа 2026 по живому наблюдению за рулём: «превысил — сказал,
а про камеру в 300–500 метрах впереди промолчал». Это не сбой, это следствие
конструкции — и её надо менять, а не подкручивать константы.

---

## Часть 1. Почему промолчало

### Камера в радиус попадала

Радиус — `max(400 м, скорость × 22 с)`, потолок 1000 м
(`AlertEngine.effectiveRadius`). На 60 км/ч это 400 м, на 80 — 489 м. Камера в
300–500 м **была внутри**, `AlertEngine` уровень выдал. Гейты направления и
коридора тут ни при чём.

### Решение промолчать принято политикой

```swift
// AlertPolicy.swift:103–116
if voice == .off      { return .silent }
if isSudden || isOverspeeding { return .urgent }
if voice == .smart    { return .silent }   // ← вот здесь
if isCrawling         { return .silent }
return context == .highway ? .calm : .brief
```

`VoiceMode.smart` стоит **по умолчанию** и означает буквально: молчать о
камере, если едешь в лимите. Логика была такая: «камеру видно на панели,
говорить не о чем, иначе голос в городе превращается в белый шум». Намерение
верное, исполнение — нет.

### Два голоса, которые друг о друге не знают

| Что говорит | Кто говорит | Знает ли о другом |
|---|---|---|
| «Превышение скорости» | `SpeedLimitService.onOverspeed` → `AlertPlayer` | нет |
| «Камера, 300 метров» | `LocationService.runAlertEngine` → `AlertPolicy` | нет |

Это и есть корень. Флаг `isOverspeedingSustained` читается **в один момент
времени**, и если к моменту, когда камера дошла до уровня оповещения, водитель
уже сбросил (или флаг дрогнул от шума GPS), решение становится `.silent`.
Слышно «превысил», не слышно «камера» — ровно то, что случилось.

### И отдельная дыра: неизвестный лимит = полная тишина

`isOverspeedingSustained` может стать `true` только если `SpeedLimitService`
знает лимит дороги. Не знает — значит превышения нет по определению, значит в
режиме «Умно» камера **никогда** не озвучивается. На дорогах без данных
приложение по умолчанию молчит про все камеры разом, и понять это по экрану
невозможно.

Это вторая причина, почему фолбэк лимита по классу дороги (см.
`plan_public_launch.md`, пункт 8) — не «улучшение аналитики», а условие
работоспособности голоса.

## Часть 2. Что построить вместо этого

### `VoiceDirector` — один арбитр на все реплики

Новый чистый `nonisolated` движок. На каждом GPS-тике получает **всю**
обстановку разом и возвращает **не больше одной** фразы:

```swift
struct Situation {
    let camera: Camera?              // ближайшая уже прошедшая гейты
    let distance: CLLocationDistance
    let level: Int                   // от AlertEngine
    let isFirstForCamera: Bool
    let speedKmh: Double
    let limitKmh: Int?               // лимит дороги, nil — неизвестен
    let overKmh: Double?             // устойчивое превышение
    let context: AlertPolicy.Context
    let familiarity: CameraFamiliarity  // своя / незнакомая
    let mode: VoiceMode
}

enum Utterance {
    case suddenPoint(Camera)                 // передвижной, тренога, ДТП
    case cameraWithOverspeed(Camera, over: Double, limit: Int)
    case camera(Camera, brief: Bool)
    case overspeedOnly(over: Double, limit: Int)
    case silent(haptic: HapticLevel)
}
```

**Приоритет — тот, что вы описали:**

1. **Внезапная точка** — всегда и срочно. Водитель не мог знать о ней заранее.
2. **Камера впереди + превышение** → одна объединённая фраза, а не две подряд:
   «Камера, 300 метров, здесь 60 — сбросьте». Сейчас это в лучшем случае две
   реплики внахлёст, в худшем — одна из них теряется.
3. **Камера впереди без превышения** → зависит от контекста:
   - трасса — полная фраза («Стационарный радар, 500 метров, справа»);
   - город — короткая («Камера, 300 метров»);
   - **своя камера** (проезжаете каждый день спокойно) — только тук.
4. **Превышение без камеры впереди** → «Превышение, здесь 60». Не чаще раза
   в `overspeedRepeatSeconds` и только при устойчивом флаге.
5. Иначе — тишина.

**Главное правило, которого сейчас нет: камера впереди перебивает
«превышение».** Превышение без камеры — это совет. Камера впереди — это деньги.
Второе всегда важнее, и говорить надо о нём.

### Почему это отдельный движок, а не правка `AlertPolicy`

`AlertPolicy` отвечает на вопрос «насколько громко», а вопрос стоит иначе —
**«что сказать прямо сейчас»**. Ответ зависит от вещей, которых политика не
видит: превышения, лимита, знакомости камеры, того, что уже было сказано
секунду назад. Пока это разнесено по двум сервисам, любое правило вида «А
перебивает Б» выразить негде.

`VoiceDirector` — чистая функция от `Situation`, значит полностью покрывается
тестами. Ровно так же, как `AlertEngine` и `AlertPolicy` (они остаются:
первый решает «пора ли», второй — «насколько громко»; директор их сводит).

### «Свои» камеры

`CameraFamiliarity` считается локально из истории проездов
(`TripHistory.passes`): камера, пройденная N раз без превышения, становится
«своей» и в городе понижается до тука. Возвращается к голосу мгновенно, если
подъезжаете к ней с превышением.

Это то, что решает главный риск удержания: дорога дом→работа — одни и те же
восемь камер дважды в день, и через две недели голос на них перестаёт быть
помощью.

## Часть 3. Режимы в настройках

### Проблема: четыре перечисления об одном

Сейчас поведение задают **четыре** независимых настройки, и пересекаются они
неочевидно:

| | Значения | О чём |
|---|---|---|
| `VoiceMode` | Молча / Умно / Обо всех | сколько говорить |
| `AlertMode` | Авто / Город / Трасса | какой контекст |
| `BackgroundAlertMode` | Все / Только радары / Выкл | что в фоне |
| `TripStartMode` | Авто / Умно / Ручной | когда начинать поездку |

Три разных «Авто/Умно» с разным смыслом. Пользователь не обязан держать эту
матрицу в голове, а результат комбинаций предсказать нельзя.

### Решение: один профиль + «Свой»

**Профиль оповещений** — одна строка в настройках:

- **Авто** (по умолчанию) — детектор сам понимает город/трассу. Камеры
  озвучиваются всегда: в городе коротко, на трассе полностью, свои — туком,
  при превышении — срочно.
- **Город** — контекст зафиксирован, коротко и часто.
- **Трасса** — контекст зафиксирован, полные фразы и заранее.
- **Тихий** — только вибрация и панель, ни слова (нынешний `off`).
- **Свой** — раскрывает подробные тумблеры: радиус, допуск превышения,
  что в фоне, отдельно голос манёвров, отдельно «свои камеры».

Старые значения мигрируют: `smart` → «Авто», `always` → «Авто» с включённым
«говорить и о своих», `off` → «Тихий». Ни одна привычка не ломается молча.

### Что меняется в поведении по умолчанию

**Главное:** «Авто» больше **не молчит** о камере, когда едешь в лимите. Именно
это молчание и выглядит как поломка — камера на карте есть, голоса нет.
В городе будет короткая фраза, на трассе полная, на своих камерах — тук.

## Часть 4. Узбекский голос

В iOS **нет узбекского голоса вообще**: проверено, 180 системных голосов,
`uz-UZ` и `uz` отсутствуют (казахского тоже нет, турецкий есть). Сейчас
`AlertPlayer` жёстко зашит на `ru-RU` (`AlertPlayer.swift:117`) — интерфейс
переведён на узбекский полностью, а голос за рулём всегда русский.

Решение — **записанные фразы**. Словарь оповещений конечный и шаблонный:

```
[тип камеры] × [дистанция] × [сторона] × [лимит] × [действие]
камера | радар | тренога | пост | ДТП
100 | 200 | 300 | 400 | 500 | 700 метров
справа | слева | впереди
здесь 40 | 50 | 60 | 70 | 80 | 90 | 100 | 110 | 120
сбросьте | превышение | маршрут перестроен | вы прибыли
```

Порядка 40–50 коротких файлов на язык, склеиваются `AVAudioPlayerNode` по
шаблону. Русский тоже стоит перевести на записи: живой голос диктора звучит
лучше синтеза и не зависит от того, какие голоса скачал пользователь.

Fallback остаётся на `AVSpeechSynthesizer` — если файла нет, синтез
проговаривает по-русски, как сейчас. Молчания быть не должно ни при каких
обстоятельствах.

## Часть 5. Батарея

Голосовой арбитр батарею не трогает — это арифметика на уже имеющихся данных.
Экономия в другом, и почти всё уже сделано (адаптивная точность GPS, реакция
на перегрев, ретайлинг геозон). Осталось:

1. **Замер на живом железе** — единственная цифра, которой нет: сколько
   процентов за час поездки. Без неё разговор про батарею беспредметен.
   Сценарий: 40 минут по городу с маршрутом, экран включён, запись до и после.
2. **Ослаблять GPS, когда камер рядом нет.** `tuneAdaptiveAccuracy` это уже
   умеет; проверить, что порог не слишком консервативный за городом, где до
   ближайшей камеры десятки километров.
3. **Не будить радио зря.** Опрос передвижных — 3 минуты; при `.reduced`
   от перегрева и в дальней поездке без камер интервал можно удваивать.

## Часть 6. Архитектурные долги, которые видно отсюда

Не срочные, но они и породили сегодняшний дефект.

- **`LocationService` — 1119 строк** и слишком много ролей: GPS, геозоны,
  поездки, водитель/пассажир, лимиты, маршрут, оповещения. Голосовой арбитр —
  повод вынести из него «оповещения» целиком в отдельный `AlertCoordinator`,
  оставив сервису живой `CLLocationManager` и режимы.
- **`MapScreen` — 1108 строк** при ориентире ARCHITECTURE.md ≤400.
- **Настройки без единого места решения.** После введения профиля матрица
  «профиль → конкретные значения» должна жить в одном типе, а не собираться по
  четырём перечислениям в трёх файлах.

### Про узбекский: готового пакета нет нигде

Проверено, а не предположено. В iOS узбекский не входит в список языков
синтеза вовсе — его нельзя ни включить, ни догрузить; на устройстве 180
голосов, из тюркских только турецкий. В Piper, лучшем офлайн-движке с
открытым кодом, узбекского тоже нет (казахский и турецкий есть). Облачные
TTS с узбекским существуют, но за рулём они не годятся: сеть, задержка и
плата за запрос — а оповещение обязано работать офлайн.

Поэтому сейчас узбекские фразы читает турецкий голос по переписанной
орфографии, а настоящим решением остаётся записанный диктор: словарь
конечный, 40–50 файлов.

Первые два — три дня, и после них приложение перестаёт молчать там, где должно
говорить. Это самое дорогое из всего списка по последствиям: молчание о камере
водитель прощает один раз.
