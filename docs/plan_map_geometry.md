# План: геометрия своей карты — без клякс, игл и дыр

Написан 27.09.2026 по снимку владельца (мост Навои через Анхор, зум ~19):
разделительная полоса вывернута «бабочкой», от неё иглы, край полотна в
ступеньках. Вердикт владельца — «так не годится».

## 0. Диагноз

**Данные не виноваты.** Дорога, мост, вода, зелень на снимке из OSM лежат
верно. Лучше OSM открытых дорог по Узбекистану нет: Overture в транспорте —
тот же OSM, ИИ-дороги Microsoft — геометрия без имён, классов и
односторонности. Менять источник — потерять атрибуты и не получить ничего.

**Виновата наша генерация поверхности** (`build_roads.py`, набор `d`):

| Что на снимке | Откуда |
|---|---|
| Тёмный крест-«бабочка» поперёк полотна | `_median_strip`: на каждом шаге берётся БЛИЖАЙШАЯ точка встречной ленты. Где ленты сходятся (мост, съезд), ближайшая точка прыгает назад — кромка идёт вспять, многоугольник сам себя пересекает |
| Длинные тонкие иглы | `build_islands`: грань графа между почти параллельными линиями проходит порог площади островка (20–1200 м²), хотя шириной она в метр |
| Ступеньки и зазубрины по краю серого | стыки полигонов полотна и перекрёстков (разобрать валидатором) |

Главное правило, которого не было: **сгенерированный многоугольник, не
прошедший проверку, не должен доехать до карты.** Полотно всё равно
нарисовано линией нужной ширины (`roads` в стиле телефона лежит ниже
поверхности), так что выброшенный кривой полигон стоит только «шва» на
перекрёстке, а оставленный — кляксы, которую видно.

## 1. Инструмент: замер и быстрая сборка

- [x] `server/surface_check.py` — валидатор поверхности: самопересечение,
      иглы (острый угол + длинное ребро), «лезвия» (компактность 4πS/P²),
      вывернутая кромка. Считает по стране и по рамке, пишет geojson
      плохих — чтобы видеть глазами.
- [x] Сборка на маке по рамке Ташкента (минуты вместо восьми часов на
      сервере) — тот же `build_roads.py`, те же экстракты.
- [x] Замер «до»: сколько плохих медиан, островков, полотна.

## 2. Починка

- [x] **Медиана.** Проекция на встречную ленту обязана идти монотонно (вперёд
      по ней, ни шагу назад); ширина между соседними шагами не прыгает больше
      чем на порог; итог проверяется на самопересечение — не прошёл → нет
      полосы.
- [x] **Островки.** Отсев «лезвий»: компактность ниже порога или вписанная
      ширина меньше метра → не островок.
- [x] **Общие ворота поверхности** — последним шагом перед записью тайла: всё
      AREA_ROAD/JUNCTION/MEDIAN проходит валидатор; счётчик выброшенного — в
      отчёт сборки и в `roads_gate.py` (рост выброшенного = регрессия).
- [x] Края полотна: дуга ставилась и на внутренний угол (условие в `_arc` не срабатывало) — починено; ступеньки — ширина линии по всей ленте.
- [x] Тесты на каждый класс — на настоящей геометрии моста Навои.

## 3. Проверка и выкладка

## 6. До уровня Яндекса — чего не хватает и почему

Яндекс рисуют картографы: полосы, бордюры, тротуары, деревья и здания
отрисованы руками. Из OSM автоматически так не выйдет, но ближе — можно:

- [ ] **Скругление бордюра на углах** (радиус по классу) — сейчас угол
      перекрёстка острый. Отдельный многоугольник-галтель на каждый угол
      между соседними ногами; красится цветом полотна — нужен слой в стиле
      телефона (задача приложения).
- [ ] **Цвет узла по классу** — стиль телефона красит все узлы цветом
      проспекта; передать `cls` у вида 8 и красить по нему (приложение).
- [ ] **Тротуары и зебры на всех подходах** — тротуары в данных есть
      (набор t, 9 334 в Ташкенте), в стиль MapLibre не выведены (приложение).
- [ ] **Подписи крупнее и контрастнее** — данные есть (90–98 % улиц с именем),
      стиль телефона их гасит (приложение).
- [ ] **Места и POI** — слой `places` в MVT уже есть, стилю нужен слой.
- [ ] Проверка на телефоне на зумах 17–19 (разметка и светофоры — в тайлах есть).
