# CarPlay: исследование и замеры — 11.10.2026

Почему CarPlay «не работает» который день. Источники: документация Apple
(CPWindow, CPMapTemplateDelegate, «Displaying Content in CarPlay»), CarPlay
Developer Guide (июнь 2026), WWDC22 10016 и WWDC25 216, форумы Apple
(730949, 777989, 740579, 790895), исходники MapLibre ios-v6.29.0 и Mapbox
Navigation iOS, журналы телефона (carplay3–5.logarchive), проверка в CarPlay
Simulator с телефоном и симуляцией маршрута.

## 1. Перетаскивание пальцем
- Окно карты касаний не получает никогда: «The base view of a navigation
  app does not receive tap or drag events» (CPWindow). Жест приходит только
  в CPMapTemplateDelegate (didBegin/didUpdate/didEndPanGesture).
- Эти вызовы есть не во всех машинах: «CarPlay doesn't call this method when
  connected to some CarPlay systems». Поэтому кнопка осмотра обязательна.
- CarPlay Simulator перетаскивание не присылает: инженер Apple на форуме
  (730949) — даже образец Apple его не получает. Проверять в машине с
  сенсорным экраном. В 2.2.8 жест пишется в журнал («перетаскивание пальцем»).
- Щипок (iOS 26) — тоже только в машинах с мультитачем.

## 2. Застывшее и пустое окно
- Apple: «You must set both the window's root view controller and the scene's
  root template before returning from this method» (didConnect). 2.2.6 ставил
  корень позже → хост CarPlay «not considered visible», «Not installing
  presentation view» → пустой экран. 2.2.5 подменял корень сторожем → машина
  показывала старый слой → застывший кадр. 2.2.7: постоянный корень.
- MapLibre 6.29: карта, созданная при applicationState == .background,
  стартует «спящей» и будится не всегда. 2.2.8: содержимое строится только
  в активном приложении.
- Такт не от экрана машины встаёт при погашенном экране телефона (777989):
  пульс сторожа в 2.2.8 только пишется в журнал, чинит лишь отставание GPS.
- SwiftUI внутри CPWindow на форуме (740579) не обновлялся по @State, UIKit в
  том же окне — обновлялся. Если застывание вернётся — переносить окно машины
  на UIKit с MLNMapView напрямую.
- Apple: в окне машины рисовать только карту, без панелей и оверлеев
  (Guideline 2). Наш HUD со скоростью — риск ревью; спидометр так делают и
  другие (Яндекс), но держать в уме.

## 3. Карточка манёвра без стрелки и текста
- В 2.2.4 включили метаданные для приборки
  (mapTemplateShouldProvideNavigationMetadata = true). Руководство требует для
  них тип манёвра, тип перекрёстка, сторону движения и состояние манёвра —
  двух полей у нас нет. С тех пор карточка показывала одно расстояние.
  Mapbox метаданные не включает. 2.2.8: выключено, плюс начальная оценка в
  манёвре и строка журнала «манёвр в машину: …».

## 4. Поездка в реальном времени (2.2.7, симуляция маршрута по Амира Темура)
Спидометр, знак лимита (60 с красной кромкой при превышении, ≈70 пунктиром),
отсчёт до камер и смена камер, слежение карты, пересчёт прибытия — работают.

| Режим | RadarMap CPU, сред. | p95 | Память |
|---|---|---|---|
| Стоим, маршрут активен | 0,8 % | 1,1 % | 278 МБ |
| Нажатия и осмотр | 5,8 % | 33 % (пик) | 326 МБ |
| Едем 60 км/ч | 35 % | 52 % | 302–310 МБ |

Во время езды системный компоновщик (backboardd) — ещё 32 %. Профиль: 72 %
времени RadarMap — главный поток, из них около двух третей — отрисовка
MapLibre внутри прохода отображения UIKit. Кадры уже ограничены 30 в секунду.
Дальше резать: реже двигать камеру, без объёмных домов в машине, маркер
положения не перекладывать в источник данных каждый кадр.

## 5. Почему так долго
- Нет отладки на телефоне: в Xcode на этом Mac нет аккаунта команды, каждая
  проверка — сборка TestFlight (15–20 минут) и журнал по паролю.
- В Xcode 27 нет Simulator с экраном CarPlay — локально CarPlay не проверить.
- CarPlay Simulator не умеет перетаскивание и заблокированный телефон.
Добавить Apple ID команды в Xcode → Settings → Accounts — и цикл
«правка → проверка в машине» станет минутным.
