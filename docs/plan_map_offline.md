# План: карта в приложении — онлайн без скачивания, офлайн по регионам, плавно

Написан 07.10.2026 по трём разборам: код приложения (`Features/Map/Engine/*`),
замеры данных (кандидат страны 07.10, `uz.mbtiles`, заголовки nginx) и практика
отрасли (MapLibre Native 6.x, Organic Maps, OsmAnd, Google, Apple).
Продолжение `plan_map_omt.md` §3: тот план встраивает основу, этот —
решает, КАК данные попадают на телефон и почему карта не дёргается.

## 0. Что сейчас (факты)

- Приложение рисует движком только главный экран карты (`MapBase.engine`),
  стилем, вшитым в код (`EngineMapStyle`, ~25 слоёв, только наш MVT).
  Основы OMT, деревьев, парковок, ограждений, стрелок, подписей мест в
  приложении НЕТ — всё сделанное с 28.09 видно только в превью.
- Приборка — эскиз (`RoadSketchView`) поверх Apple; CarPlay — MapKit/эскиз.
- Офлайна нет: только ambient-кэш движка 200 МБ (LRU, срок по заголовкам).
- Индекс проверки — один на страну: `mvt_index.json` 23,6 МБ, разбор ~100 МБ
  транзиентно (73 отстрела по памяти за 40 суток), обновляется раз за процесс.
  С основой OMT добавится ещё 27,2 МБ.
- Тайлы отдаются с `max-age=300` и без версии в адресе: перекачка каждые
  5 минут, а после публикации в середине сеанса новые тайлы не сходятся со
  старым индексом — дырки до перезапуска.
- Шрифты качаются по сети (101 МБ на сервере), а нужно ~1,4 МБ.
- Дороги качаются дважды: JSON-тайлы эскиза и MVT — из одной сборки.

## 2. Архитектура

### 2.1 Два режима, один стиль
- **Онлайн (по умолчанию, ничего не скачивать):** тайлы стримятся с сервера,
  проверяет `EngineTileGuard`, кэш движка держит то, где человек ездит.
- **Офлайн-регион (по желанию или сам):** один файл PMTiles на область,
  движок читает его локально (`pmtiles://file://…`) — ни сети, ни запросов.
- Стиль один (вшитый ресурс из `make_style.py --app`, `plan_map_omt.md` §3.1);
  для каждого источника адрес подставляется при сборке стиля: файл региона,
  если он установлен и проверен, иначе сервер.

### 2.2 Онлайн: быстро и без дыр
- **Версия в адресе тайла:** `/radarmap/v{N}/mvt/…`, `/v{N}/omt/…`; публикация
  кладёт новую папку, старую держит неделю. Тогда `Cache-Control: max-age=1 год,
  immutable` безопасен: тайл по адресу никогда не меняется, и перекачка каждые
  5 минут исчезает. Индекс — короткий срок (5 мин) и ETag.
- **Индекс корзинами вместо одного файла:** подписанный корень (`root.json`,
  ~60 КБ: версия N + sha256 каждой корзины) + бинарные корзины по клетке z10
  (16–55 КБ, sha каждого тайла MVT и OMT в ней). Телефон берёт корень при
  старте и при выходе из фона, корзины — по мере движения (3×3 вокруг себя,
  вперёд по маршруту). Ушёл разбор 50 МБ JSON и сотня МБ памяти.
- **Смена версии в середине сеанса:** новый корень → новые адреса v{N+1};
  старые тайлы в кэше движка доживают своё, дыр нет.
- Шрифты (1,4 МБ) и спрайт (264 КБ) — в бандле (правило «без сетевых шрифтов»).

### 2.3 Офлайн-регионы
- Сервер (мак) после сборки режет страну на ~15 файлов: 12 областей,
  Каракалпакстан, Ташкент-город (и Самарканд-город отдельно, он маленький).
  В каждом — OMT z0–14 + наш MVT z11/z15, формат PMTiles.
- `regions.json` подписан тем же ключом (Ed25519): для каждого региона —
  версия, размер, sha256 файла, рамка. Публикация — `publish_roads.sh` тем же
  шагом, что тайлы: одна сборка, одна подпись.
- Телефон качает файл своим фоновым `URLSession` (докачка, экран выключен,
  Wi-Fi), проверяет sha256 всего файла (CryptoKit, 100 МБ < 0,2 с), кладёт
  атомарно под именем `<регион>-<версия>.pmtiles`, перезагружает стиль и только
  потом удаляет старую версию. Не сошлось — файл удаляется, старая остаётся.
  `MLNOfflinePack` НЕ используем: фоновую загрузку он не умеет.
- **Сам, без вопроса:** область дома (из `FrequentPlaces`) докачивается на
  Wi-Fi и зарядке. В настройках — «Офлайн-карты»: список областей с размером,
  «Вся страна ~350 МБ», удалить, место на диске.
- Обновление раз в месяц вместе со сборкой дорог; проверка `regions.json` раз
  в неделю; без диффов (при месячной свежести полный файл проще и надёжнее).
  Старый регион не блокируется — через ~6 месяцев мягкая подсказка обновить.
- Камеры и оповещения от карты не зависят никак — как сейчас.

### 2.4 Плавность (ведение за машиной, держатель, жара)
- **Слоёв в стиле приложения < 100.** Сейчас превью — 168: для приложения
  отдельный профиль `make_style.py --app` без декора (зерно асфальта,
  штриховки, тени домов на дальних зумах), каждому слою — свои `minzoom/maxzoom`
  (z11-источник рисуется только до ~z12, z15 — с 14,6).
- **Никаких** `fill-extrusion`, рельефа и теней-узоров в режиме ведения.
- **Позиция машины** — слоем местоположения движка, а не пересозданием
  GeoJSON на каждый фикс. **Маршрут** — постоянный источник, пройденное —
  `line-trim-offset`/градиент, а не пересылка всей линии каждые 15 м.
  **Камера впереди** — `feature-state`, а не новый GeoJSON.
- **Тепловая лестница** (`ThermalService` → движок):
  `.nominal` — 60 к/с; `.fair` — `tileLodZoomShift −0.5`; `.serious` — 30 к/с,
  сдвиг −1, без декоративных подписей и узоров; `.critical` — ещё и без
  `tileCacheEnabled`. Предупреждение о памяти — то же, что `.critical`.
- `frustumOffset` под верхний HUD: не грузить и не рисовать то, что под ним.
- Один `styleJSON` на холодном старте (корень индекса берётся до карты, а не
  после первой отрисовки); смена дня/ночи — без пересборки всего стиля.
- Ambient-кэш 200–300 МБ остаётся: для тех, кто ничего не скачал.

### 2.5 Один движок (позже)
Приборка и CarPlay переходят на тот же движок и те же данные; JSON-тайлы
эскиза остаются только как источник для логики (лимиты, «на какой я улице»),
пока она не переедет на MVT. До тех пор у обоих — свои выключатели.

## 2.6 Шаг 1 сделан (07.10.2026) — контракт для приложения

Сервер уже отдаёт всё, что нужно шагам 2–3; старые адреса работают как раньше.

- **Корень:** `https://soulmed.uz/radarmap/tiles_root.json` — `SignedPayload`
  (тот же ключ `AppConfig.otaPublicKeyB64`), `Cache-Control: max-age=300`.
  Полезная нагрузка:
  `{"version": N, "bucketZoom": 10, "sets": {"mvt": {"path": "mvt", "ext": "mvt",
  "tiles": …, "buckets": {"<bx>_<by>": sha256hex, "low"?: …}}, "omt": {"path": "omt",
  "ext": "pbf", …}}}`.
- **Корзина:** `/radarmap/v/<N>/idx/<набор>/<bx>_<by>.bin` — формат RMTI v1, байт
  в байт как `TileDigestIndex.serialized()`, читается `TileDigestIndex(serialized:)`.
  Имя корзины тайла: `x >> (z−10)`, `y >> (z−10)`; при z < 10 — `low`.
  Проверка: sha256 корзины == значение в корне. Тайла нет в корзине — пустой тайл.
- **Тайл:** `/radarmap/v/<N>/<path>/<z>/<x>/<y>.<ext>`, `Cache-Control: public,
  max-age=31536000, immutable`; sha256 тела (после снятия gzip) == запись корзины.
  Размеры: MVT 582 корзины (медиана 6,6 КБ, макс 40 КБ), OMT 882 (11 / 17 КБ).
- **Выпуск:** `bash server/publish_tileset.sh` — после `publish_roads.sh` и
  `publish_omt.sh`; замораживает опубликованное жёсткими ссылками, проверяет
  выборку тайлов против подписанных индексов, корень кладёт последним, держит
  два последних выпуска. Первый выпуск: v2610071018.
- **Шрифты в бандл:** `python3 server/omt/glyph_subset.py <glyphs> <выход>
  --check <roads/places/points.geojsonl>` — 3 начертания × 6 диапазонов, 1,5 МБ;
  вне покрытия только 11 названий арабицей.
- **Ещё не сделано на сервере:** профиль `make_style.py --app` (< 100 слоёв) —
  делать вместе с шагом 2, глядя на телефон; нарезка регионов PMTiles — шаг 4.

## 2.7 Серверная половина шага 4 сделана (07.10.2026) — контракт регионов

- **Список:** `https://soulmed.uz/radarmap/regions.json` — `SignedPayload`
  (ключ `otaPublicKeyB64`), кэш 5 мин. Полезная нагрузка:
  `{"version": N, "cellZoom": 12, "regions": [{"id": "UZ-TK", "name": {"uz", "ru"},
  "bbox": [запад, юг, восток, север], "cells": k, "rows": [[y, x_от, x_до], …],
  "files": {"mvt": {"file", "bytes", "sha256", "tiles"}, "omt": {…}}}]}`.
  `rows` — клетки z12 региона: точка (дом, работа) → клетка → регион, без полигонов.
- **Файл:** `/radarmap/regions/<N>/<id>.<mvt|omt>.pmtiles` — PMTiles v3, тайлы
  gzip, кэш на год, Range работает (докачка). Проверка: sha256 всего файла ==
  `files.*.sha256`, затем атомарное переименование, затем перезагрузка стиля.
- **Набор v2610071033:** 14 регионов, 344 МБ. Ташкент-город 20 МБ, Ташкентская
  обл. 47, Каракалпакстан 40, Самаркандская 28, Ферганская 27, остальные 9–29.
  Каждая клетка z12 — ровно в одном регионе; 440 клеток вне страны — только онлайн.
- **Проверено:** эталонной библиотекой Protomaps `pmtiles` 4.5 (Ташкент целиком —
  755 + 274 тайла, выборки по Каракалпакстану и области) — 0 расхождений с
  исходниками; движком на маке не проверить: node-биндинг 6.4.1 PMTiles ещё не
  умеет — это остаётся шагу 0 на iPhone (6.29).
- **Сборка:** `region_boundaries.sh` (osmium на VPS) → `build_regions.py` (~30 с)
  → `publish_regions.sh` (подпись на маке, sha каждого файла на сервере,
  regions.json последним, два набора). Код: `pmtiles.py` (запись/чтение v3,
  stdlib), тесты `test_pmtiles.py`, `test_build_regions.py`.

## 2.9 Пробки — разбор (07.10.2026), в коде не делалось

Своего источника нет, а чужие закрыты:
- Яндекс, Google, 2ГИС — данные о пробках по их условиям брать нельзя
  (то же правило, что для геометрии карты в HANDOFF).
- TomTom / HERE Traffic API — платно, покрытие Узбекистана слабое; и это
  внешний сервис в рантайме — против принципа «ничего чужого в рантайме».
- **Свои данные — единственный честный путь**: обезличенные скорости по
  сегментам дорог от самих водителей RadarMap. Но сегодня приложение
  принципиально НЕ шлёт координаты (UsageStats, правило приватности), и это
  нельзя ломать молча. Нужен отдельный дизайн: агрегирование на телефоне до
  «сегмент OSM → средняя скорость за 5 мин», без треков и идентификаторов,
  k-анонимность на сервере (≥ N машин на сегменте), явный тумблер согласия.
  Имеет смысл с ~1 000 активных водителей в городе; до того карта пробок будет
  пятнистой и вводить в заблуждение.
- На карте Apple тумблер «Пробки» остаётся (их данные, их условия).

## 4. Риски

- PMTiles на iOS 6.29 не проверен у нас (открытый краш #3658 у MapLibre) —
  поэтому шаг 0 первым.
- Тайлы из кэша и файла проверяются один раз (при скачивании); дальше —
  песочница приложения. Это та же модель, что у базы камер.
- Диск VPS: версии v{N} и v{N−1} + регионы ≈ +1 ГБ — свободно 18 ГБ.
