# Еженедельное обновление графа OSRM (87, 10.11.2026)

Маршруты строит граф, собранный из OSM: стенд MLD (через него идут все
маршруты приложения) и резерв CH сейчас стоят на данных от 20.10. Новая дорога, новый запрет поворота или снятый знак доходят до водителя
только с новым графом. Здесь — как обновлять его каждую неделю, не
нагружая VPS и не трогая живые файлы, пока не скажет владелец.

Сценарий: `server/osrm/graph_refresh.py`, тесты:
`server/osrm/test_graph_refresh.py` (34 случая, ~40 с, без сети и Docker;
подмена проверяется целиком на временном корне с настоящим
`traffic_customize.sh` и заглушками docker/curl).

## Что где

| Где | Что |
|---|---|
| мак, `~/RadarMapBuild/osrm/refresh/<дата>/` | выгрузка, `mld-uzbekistan/`, `ch-uzbekistan/`, `build.json`, `audit/`, `audit.json`, `audit.md`; хранятся три последние сборки и та, что сейчас боевая |
| VPS, `/opt/radarmap/osrm-mld/candidate-<дата>/` | кандидат MLD (эталон для `traffic_customize.sh`) |
| VPS, `/opt/radarmap/osrm-mld/ch-candidate-<дата>/` | кандидат CH (резерв nginx и `match` для `traffic_build.py`) |
| VPS, `…/candidate-<дата>.part/` | недолитый кандидат; следующий `upload` продолжит с первого неполного файла |

Кандидатов каждого вида на VPS — не больше двух: свежий и один прежний.
`pristine`, `a`, `b`, `current`, `bin`, `test` и всё, что смонтировано в
контейнеры, сценарий не удаляет и не меняет ни при каком раскладе; живой
сервис кандидатов не читает.

## Команды

```bash
# 1. мак, любой день после воскресенья (Geofabrik обновляется ежедневно).
#    Тяжёлое: extract ~3 ГБ в Docker; под общим замком и nice.
python3 server/osrm/graph_refresh.py build            # --date Д, --pbf файл, --threads 2
python3 server/osrm/graph_refresh.py audit            # → audit.md, код 1 — ворота не пройдены

# 2. ворота нагрузки VPS — только чтение, можно когда угодно
python3 server/osrm/graph_refresh.py gate --need-mb 1700

# 3. ночью: заливка кандидатов (код 75 — сервер занят или не ночь, повторить)
python3 server/osrm/graph_refresh.py upload --date 2026-11-10 --wait 180
python3 server/osrm/graph_refresh.py upload --date 2026-11-10 --dry-run   # план без записи

# 4. владелец: подмена (без --i-am-owner только печатает шаги)
python3 server/osrm/graph_refresh.py switch --date 2026-11-10 --kind mld
python3 server/osrm/graph_refresh.py switch --date 2026-11-10 --kind ch
```

### build

Свежая выгрузка Geofabrik (md5, не меньше 50 МБ), затем
`build_osrm_mld.sh` дважды — MLD и `--ch`, оба с `car_radarmap.lua`, тем же
образом OSRM v26.7.3 под linux/amd64, что на VPS (дайджест берётся из
`build_osrm_mld.sh`, чтобы версия жила в одном месте). Печатает время,
пики памяти каждого шага, размеры, запреты поворотов (в выгрузке /
отброшено / в графе) и число рёбер; пишет `SHA256SUMS` каждого набора для
проверки на сервере.

### audit

Поднимает в локальном Docker по очереди четыре `osrm-routed --mmap`:
старый и новый MLD (`--max-alternatives 3`, как стенд), старый и новый CH.
«Старый» — локальная копия боевого графа, которую сценарий находит сам:
набор, чьи sha совпали с манифестом на VPS (`pristine/manifest.txt` и
каталог, смонтированный в `radarmap-osrm`; ssh только на чтение). Не нашёл —
ошибка, а не сравнение с чем попало. Пары `audit_pairs.json` идут запросом
приложения (`alternatives=3`, steps, `approaches=unrestricted;curb`), теги
OSM под маршрутами — из новой выгрузки (pyosmium), разбор — `route_audit.py`.

Ворота (`GATE` в сценарии), отдельно для MLD и для CH:

| Условие | Провал, если |
|---|---|
| Пары без маршрута | их стало больше |
| Нарушения запретов поворотов (via-узел) | в первых вариантах или во всех вариантах их стало больше |
| Резкий рост времени | первый вариант медленнее ×1,2 больше чем у 10 % пар (3 из 20) |
| Варианты | всего вариантов меньше на 20 % |
| Запреты в графе | меньше на 10 % — битая или испорченная выгрузка |
| Рёбра графа | изменились больше чем на 10 % |

`upload` льёт только прошедший аудит вид.

### upload

Только при свободном сервере, по снимку VPS через ssh: ночь по Ташкенту
02:00–05:30, load average за минуту < 0,5, MemAvailable > 800 МБ, цикл
пробок не идёт (`osrm-mld/.lock`), свободно места на набор + 2 ГБ и не меньше
100 тыс. inode. Не так — с `--wait N` ждёт до N минут (проверка раз в 5 мин),
без него выходит с кодом 75 и пишет, почему. Между файлами ворота
проверяются снова, но load допускается до 1,0 (своя заливка тоже грузит);
кончилась ночь — остановка, недолитое остаётся в `.part`.

`scp -l 40000` (Кбит/с, ~5 МБ/с) по файлу в `candidate-<дата>.part`,
затем на сервере `nice -n 19 ionice -c3 sha256sum -c` и переименование в
`candidate-<дата>`. Битые файлы удаляются, следующий запуск их перельёт.
После — чистка: кандидаты этого вида старше прежнего и недолитые `.part`
других дат (`nice`/`ionice`, ничего смонтированного). `.failed` от
неудачной подмены оставляется владельцу.

### switch — делает владелец

Без `--i-am-owner` только печатает сценарий. Всё внутри `main` — `bash -s`
читает текст со stdin, и дочерний процесс не съест его хвост.

**MLD** (стенд, через него идут маршруты):

1. `sha256sum -c` кандидата; образ кандидата тот же, что у
   `radarmap-osrm-mld` (граф другой версии `osrm-routed` не откроет).
2. Замок цикла пробок — тот же `mkdir osrm-mld/.lock`, что в
   `traffic_customize.sh`; пока он наш, cron-цикл пишет «пропуск». Держится
   только на время переименований (цикл снимает замок старше 30 мин).
3. Прежний `pristine.prev-*` удаляется (слоты держат свои жёсткие ссылки),
   `pristine → pristine.prev-<дата>`, `candidate-<дата> → pristine`, замок
   снят.
4. `traffic_customize.sh --force` пересобирает запасной слот с нового
   эталона, перезапускает стенд и пробует маршрут (это его штатный путь).
   Готово, только когда `.ebg` в `current` — тот же inode, что в
   `pristine`: цикл, занятый cron-ом, отвечает «пропуск» с кодом 0, и без
   этой проверки подмена считалась бы сделанной на старом графе.
5. Проба 8094: Чиланзар → Юнусабад и Ташкент → Самарканд, `code: Ok`.
6. Провал — откат: под замком `pristine → candidate-<дата>.failed`,
   `pristine.prev-<дата> → pristine`, снова слот и проба. На секунды
   перезапусков nginx отдаёт резерв CH.

**CH** (резерв nginx и `match` пробок):

1. `sha256sum -c`; источник, образ и команда работающего `radarmap-osrm`
   записываются (`docker inspect` → `/opt/radarmap/radarmap-osrm.inspect-<дата>.json`);
   образ кандидата должен совпасть.
2. `ch-candidate-<дата> → /opt/radarmap/osrm-ch-<дата>`.
3. Под замком цикла пробок (чтобы стенд не перезапустился в те же секунды
   и nginx не остался без обоих апстримов): `docker rm -f` + `docker run`
   тем же образом по id, `--mmap 1`, `127.0.0.1:8092`, проба.
4. Провал — контейнер с прежним каталогом и прежней командой из
   `docker inspect`, новый каталог → `ch-candidate-<дата>.failed`.
   `traffic_build.py` один-два цикла (2 мин) не получит `match` — это всё.

Порядок: сначала MLD, проверить приложением, затем CH той же ночью —
`traffic_edges.model_kmh` берётся из `match` CH, а уровень пробки на стенде —
против скоростей его графа; профили одинаковые, но рёбра с изменившимся
`maxspeed` (см. Ангрен ниже) лучше переводить вместе. Прежние каталоги
(`pristine.prev-<дата>`, прежний CH) — до следующей недели, это откат;
`/opt/radarmap/osrm` (июльский граф и выгрузка, которую читают
`update_roads.sh` и лимиты) не трогать никогда.

## Как часто

Раз в неделю: `build` + `audit` в любой день после воскресенья на маке,
`upload` следующей ночью, `switch` — когда владелец посмотрит `audit.md`.
Сборка и аудит — ~10 мин на маке, заливка ~6 мин ночью; сервер ничего не
собирает. Пропущенная неделя ничего не ломает: кандидат просто старше.

## Риски

- **Цикл пробок и новый эталон.** `traffic_customize.sh` берёт эталон
  каждый цикл, ключи файла скоростей — id узлов OSM, они переживают
  пересборку. Слот, оставшийся от старого эталона, держит его файлы
  жёсткими ссылками, пока его не перепишет следующий цикл с изменениями —
  на диске до ~0,9 ГБ лишнего на неделю.
- **Память мака.** Extract — 2,9–3,0 ГБ при Docker Desktop 4 ГБ, рядом
  контейнеры другого проекта (~330 МБ). Код 137 — поднять память Docker
  или собирать без соседей; `--threads` больше 2 поднимает пик.
- **Альтернативы MLD** могут уменьшаться от сборки к сборке (см. выше);
  ворота ловят только заметное падение.
- **Нарушения запретов** судятся только для via-узла (как в
  `route_audit.py`); запреты через путь (via=way) аудит не проверяет.
- **Аудит — 20 пар.** Он ловит битую сборку и грубые регрессии, а не
  каждую улицу; новый граф с изменённым `maxspeed` честно меняет ETA.
- **Канал.** `scp` по файлу — 53 ssh-соединения за заливку; `-l` держит
  ~5 МБ/с, сеть соседей остаётся.
- **Версия OSRM.** Граф собирается тем же дайджестом, что на VPS; обновлять
  образ — только вместе со всеми тремя графами.
