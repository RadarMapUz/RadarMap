# План: 3D-машинка и движение по полосам

Написан 06.10.2026 по запросу владельца: «у нас 3D-карта — машинка, и как
она переходит по полосам, симуляция».

## Что уже сделано (прототип)

`tools/drive_sim/` — страница превью на MapLibre GL JS:
- `make_route.py` — маршрут из НАШЕЙ сети (та же, что в тайлах): цепочка
  одной ленты улицы, у каждой точки ширина ленты и число полос;
- `drive_sim.js` — машина из объёмных примитивов (кузов, кабина-стёкла,
  крыша, колёса, фары, стопы, поворотники) как `fill-extrusion` из GeoJSON,
  обновляется каждый кадр; едет 55 км/ч по центру своей полосы
  (`-ширина/2 + ширина_полосы·(i+½)` вправо от оси); перестраивается в
  соседнюю полосу S-кривой за 3,2 с, за 1,5 с до манёвра мигает поворотник;
  кузов поворачивается по боковой скорости; камера ведёт машину сзади в
  наклоне 62° и плавно доворачивает;
- `?t=секунды` — детерминированный кадр (зерно `?seed=`) для проверки.

Запуск: `python3 tools/drive_sim/make_route.py roads.geojsonl "Bunyodkor shoh
ko'chasi" 69.2030 41.2700 web/route.json`, затем `drive.html` в превью.

Почему примитивы, а не 3D-модель: тот же `fill-extrusion` из источника-фигуры
есть и в MapLibre Native на телефоне (`MLNShapeSource` + слой выдавливания),
то есть прототип переносится в приложение без сторонних 3D-библиотек и без
второго движка рендера.

## Что будет в симуляторе (цель)

Симулятор — «прогон маршрута» прямо на нашей карте: проверить, как карта и
навигатор ведут себя в пути, не выезжая из дома. Полностью на наших данных.

| Что видно | Как работает |
|---|---|
| 3D-машина на маршруте | едет по центру своей полосы, кузов поворачивает в повороты и при перестроении |
| Маршрут из точки А в Б | OSRM (наш сервер) → по нему граф полос |
| Перестроения заранее | за 300–150 м до манёвра машина встаёт в нужную полосу по `turn:lanes`; поворотник, S-кривая |
| Повороты на перекрёстках | по связям полос через узел: из левой — налево, из правой — направо |
| Светофоры | у стоп-линии машина тормозит на красном (цикл условный), трогается на зелёном |
| Скорость | ограничение участка из нашей базы лимитов; плавный разгон и торможение |
| Камеры | при подъезде — то же предупреждение, что в поездке (голос и HUD), по нашему конвейеру алертов |
| Подсказка полосы | плашка «займите 2-ю полосу» со стрелками подхода — как будет в навигаторе |
| Камера обзора | за машиной (навигатор), сверху (2D), «вертолёт» — переключение кнопкой |
| Управление | старт/пауза, скорость ×1/×2/×4, перемотка, случайные перестроения вкл/выкл |
| Отладка | число полос и ширина участка, номер полосы, откуда взята полоса (тег/угадано) |

Чем он полезен кроме красоты:
- проверка карты: где полосы «рвутся», узел раздут, стрелки не там — видно
  на ходу, а не на статичном снимке;
- проверка алертов камер и подсказок полосы без реальной поездки;
- демонстрация приложения (видео для App Store и инвесторов).

## Дальше

### 1. Граф полос вместо одной ленты (2–3 дня)
- Полоса как отдельная линия: смещение от оси ленты, её начало и конец.
- Связи полос через перекрёсток — по `turn:lanes` (уже читаем: стрелки) и
  по геометрии съездов; без тега — правая полоса направо, левая налево.
- Машина едет по маршруту из OSRM, а не по одной улице: на подходе к манёвру
  заранее перестраивается в нужную полосу.

### 2. Подсказка полосы в навигаторе (3–4 дня) — польза для водителя
- Перед манёвром — «займите 2-ю полосу» с картинкой стрелок подхода
  (`turn:lanes`), как у Яндекса.
- Машина на карте перестраивается так же, как советует голос.
- Где `turn:lanes` нет — подсказка не показывается (никаких догадок про ПДД).

### 3. Машина в приложении (2–3 дня, нужна сессия с Xcode MCP)
- `EngineMapView`: источник-фигура «моя машина» + слой выдавливания над
  дорогами, под подписями; позиция — от `RoadSnapper` (уже держит отрисовку
  на оси дороги), полоса — по боковому смещению от оси.
- Честность: GPS не различает полосы (точность 3–10 м), поэтому на телефоне
  машина рисуется по центру ленты, а «перестроение» — только в режиме
  симуляции маршрута и в подсказке полосы, не как «вы в полосе 2».
- Производительность: 11 многоугольников на кадр, обновление ≤ 30 Гц,
  только при открытом навигаторе; на `.reduced` по нагреву — плоская стрелка.

### 4. Вид машины (1–2 дня)
- Скруглённый кузов (больше граней), тень на асфальте, тёмная тема.
- Выбор цвета в настройках.

## Риски

- `fill-extrusion` не умеет скругления и текстуры — машина «кубическая».
  Если нужен реализм модели, следующий шаг — glTF через свой слой рендера
  (Metal на iOS), это неделя и отдельный движок; пока не советую.
- Нативный движок ограничивает наклон камеры 60°, у прототипа 62° — в
  приложении взять 60°.
