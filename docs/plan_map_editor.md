# Конструктор карты: свой слой поверх OSM

Составлен 25 августа 2026, переписан подробно по требованию заказчика.

Задача: в панели на сервере строить собственный слой поверх OSM — светофоры,
развороты, полосы, мосты, положение камер, а где надо и свою геометрию. При
рисовании объект **сам примагничивается к дороге**. Слой живёт годами, OSM под
ним обновляется каждое воскресенье, и ни то, ни другое не должно ни ломаться,
ни лагать.

> **Клиентская половина нулевого этапа уже сделана** (25 августа):
> `SketchPoint`, набор тайла `_p`, распаковка, отбор по охвату, отрисовка
> пиктограммой, 699 XCTest. Осталась серверная: таблица, редактор, экспорт,
> запекание.

---

## 1. Три закона, из которых выводится всё остальное

**Закон 1. Свой слой не трогает OSM.** База пересобирается из свежего
экстракта каждое воскресенье. Любая правка, внесённая «внутрь», будет стёрта
следующим прогоном. Приём уже проверен на камерах: решения модератора копятся
в `overrides`, живая база о них не знает, они накладываются при публикации.

**Закон 2. Ничего не публикуется из панели.** Правки копятся в таблице;
подписывает и выкладывает владелец со своей машины. Взломанный сервер не
должен уметь дорисовать дорогу телефонам. Это же правило действует для камер
и дорог, и оно не обсуждается.

**Закон 3. Автоматика чинит только то, что может проверить.** Сдвиг на два
метра после обновления OSM — чинит сама. Дорога, к которой правка была
привязана, исчезла — не чинит, а спрашивает. Граница проведена явно в §5, и
она важнее удобства: данные, нарисованные руками, не с чем сверить, кроме
рук, которые их нарисовали.

## 2. Что именно можно построить

### 2.1. Точки

| Вид | Где стоит | Что хранит сверх координаты |
|---|---|---|
| Светофор | узел перекрёстка | к какому подъезду относится (азимут) |
| Лежачий полицейский | ось дороги | — |
| Стоп-линия | ось дороги | азимут подъезда |
| Разворот | ось дороги | разрешён / запрещён, на какую проезжую часть |

### 2.2. Свойства существующей дороги

Геометрии не добавляют вовсе — это поля у линии, которая уже есть.

| Свойство | Значение | Куда попадает на телефоне |
|---|---|---|
| Полосы | число + куда с каждой можно | **готовый пузырь полос** (уже написан) |
| Односторонность | да / нет / против точек | шевроны, склейка, схлопывание |
| Уровень | мост / земля / тоннель | послойная отрисовка (уже написана) |
| Запрет поворота | из сегмента в сегмент | маршрутизатор, потом |

### 2.3. Своя геометрия

Дорога, которой нет в OSM; съезд; линия разворота. Самый дорогой вид: его не
с чем сверить, и он требует вечной поддержки — см. §6.

### 2.4. Камеры

Уже работают на `/cameras/<id>/map`. Конструктор их **поглощает**, а не
дублирует: та же карта, тот же снап, тот же круг в 500 м.

## 3. Магнит: как объект садится на дорогу

Это то, ради чего конструктор вообще имеет смысл. Поставленный «на глаз»
светофор промахивается на десяток метров, и на схеме он окажется в поле.

### 3.1. К чему магнитится

К оси дороги **из наших же тайлов** — не из Яндекса и не из сырого OSM. Это
принципиально: в панели ты видишь ровно ту геометрию, которая поедет на
телефон, вместе со всей генерализацией. Иначе рисуешь по одной карте, а
получаешь другую.

### 3.2. Пороги

| Порог | Значение | Почему |
|---|---|---|
| Радиус захвата | 25 м | дальше это уже не «на дороге» |
| Захват узла | 15 м | светофоры и стоп-линии стоят на перекрёстках |
| Неоднозначность | 3 м | две дороги ближе трёх метров друг к другу — не гадаем |
| Мягкий магнит | 6 м | ближе — тянет, дальше — курсор свободен |

### 3.3. Что делает магнит

1. Курсор в радиусе захвата — точка прилипает к **проекции на ось**, а не к
   ближайшей вершине: между вершинами бывает сотня метров.
2. В радиусе захвата узла — прилипает к **узлу перекрёстка**. Для светофора
   это поведение по умолчанию: он стоит на перекрёстке, а не посреди улицы.
3. Две дороги на равном удалении (разница меньше 3 м) — **магнит не решает
   за человека**: обе подсвечиваются, объект не ставится до выбора. Это
   типичный случай проспекта с дублёром, и угадывание там даёт разворот не с
   той проезжей части.
4. Дальше радиуса захвата — точка ставится свободно и помечается «вне
   дороги». Не запрещаем: бывают объекты на площадях и парковках. Но ворота
   публикации о ней спросят (§7).

### 3.4. Что сохраняется в базу

Три вещи, и все три нужны:

- **`raw`** — куда человек ткнул на самом деле;
- **`snapped`** — куда магнит посадил;
- **`anchor`** — описание дороги без её id: класс, азимут в точке, имя,
  и `osm_fingerprint` окрестности.

`raw` хранится ради §5: когда OSM обновится, пересаживать объект надо от
исходного намерения человека, а не от прошлой посадки — иначе объект будет
уползать понемногу каждую неделю.

## 4. Данные: от клика до пикселя

```
панель ──► таблица map_edits ──► экспорт edits.json ──► ЗАПЕКАНИЕ в тайлы
                                                    └─► подписанный индекс ──► телефон
```

### 4.1. Таблица

```sql
CREATE TABLE map_edits(
  id           INTEGER PRIMARY KEY,     -- свой, никогда не из OSM
  kind         TEXT NOT NULL,           -- traffic_light | u_turn | lanes | …
  status       INTEGER NOT NULL,        -- 0 черновик 1 принято 2 опубликовано 3 снято
  geom         TEXT NOT NULL,           -- JSON: точка или ломаная (snapped)
  raw          TEXT NOT NULL,           -- JSON: куда ткнул человек
  anchor       TEXT,                    -- JSON: класс, азимут, имя дороги
  props        TEXT,                    -- JSON: по виду объекта
  fingerprint  TEXT,                    -- хэш окрестной геометрии OSM
  note         TEXT,                    -- зачем; через полгода спасёт только это
  author       TEXT NOT NULL,
  created      INTEGER NOT NULL,
  updated      INTEGER NOT NULL,
  version      INTEGER NOT NULL         -- оптимистическая блокировка
);
CREATE INDEX idx_edits_tile ON map_edits(kind, status);
```

История не удаляется: `status = 3` вместо `DELETE`. Ручная работа —
единственные данные в системе, которые нельзя восстановить пересборкой.

### 4.2. Формат на проводе

Точки едут отдельным набором тайла — `road2_{тайл}_p.json`, той же формой
записи, что и дороги, но с ОДНОЙ координатой:

```
{"version":2,"roads":[[вид, биты, [lat, lon]], …]}
```

Полосы едут **пятым элементом записи дороги** — не отдельным слоем: они
свойство линии, а не объект.

Своя геометрия едет в те же наборы `_s`/`_f`, что и OSM-дороги, с битом
«нарисовано руками» — телефону он не нужен, а панели нужен, чтобы отличать
своё от чужого в §5.

### 4.3. Почему запекать, а не возить отдельным файлом

Отдельный `edits.json` пришлось бы качать, разбирать и **сливать с дорогами
на телефоне** — вернуть туда работу, которую только что убрали. Запечённые
правки не стоят телефону ничего: он получает готовый тайл.

Цена — правки доезжают с публикацией тайлов. Она невелика: сборка при готовом
экстракте занимает минуту, значит публиковать можно по требованию.

## 5. Когда OSM обновился: очередь изменений

Раздел, ради которого стоит городить всё остальное.

### 5.1. Что считает еженедельная сборка

Помимо тайлов — `osm_diff.json`:

- дороги, **появившиеся** с прошлой сборки;
- дороги, **исчезнувшие**;
- дороги, **сдвинувшиеся** больше чем на 5 м;
- для каждой нашей правки — сошёлся ли `fingerprint`.

### 5.2. Что делает автоматика сама

| Что случилось | Действие |
|---|---|
| Отпечаток сошёлся | ничего, правка едет дальше молча |
| Дорога сдвинулась ≤ 3 м | пересаживаем от `raw`, пишем в лог |
| Сдвинулась 3–15 м | пересаживаем, **помечаем «проверить»**, но публикуем |
| Сдвинулась > 15 м | **снимаем с публикации**, в очередь |
| Дорога исчезла | снимаем с публикации, в очередь |
| Появилась новая дорога ближе 20 м к нашей нарисованной | в очередь: «OSM догнал» |

Граница проведена по одному признаку: **автоматика вправе двигать объект,
но не вправе решать, что он больше не нужен.**

### 5.3. Страница «Что изменилось»

Новая вкладка панели, по важности сверху вниз:

1. **OSM догнал нас** — рядом с нашей нарисованной дорогой появилась
   настоящая. Показываем обе на карте, одной кнопкой «снять свою».
   Это и есть ответ на «своя дорога живёт вечно»: она живёт, пока OSM её не
   догнал, и панель сама скажет, когда это случилось.
2. **Правки, потерявшие опору** — дорога исчезла или уехала далеко.
3. **Правки, пересаженные автоматикой** — просто список, чтобы видеть, что
   происходило.
4. **Новое и исчезнувшее в OSM** по районам — фон, чтобы замечать крупное:
   открылась развязка, закрыли улицу.

Ничего из этого не применяется само. Один клик человека — и правка снимается,
подтверждается или переносится.

## 6. Своя геометрия: когда её рисовать

Заказчик прав: новую дорогу иногда **надо** оставить у себя — OSM догонит не
завтра, а ездить по ней сегодня.

Поэтому не запрещаем, а обставляем:

1. Своя дорога **всегда помечена** и всегда видна в панели отдельным цветом.
2. У неё **обязательное поле «почему»**: «нет в OSM», «OSM неверен»,
   «временная схема движения».
3. **Срок пересмотра.** Временная схема — 90 дней, «нет в OSM» — 180. Срок
   вышел — правка в очередь, не снимается сама.
4. Панель **сама предложит снять**, когда OSM догонит (§5.3).
5. В той же карточке — кнопка **«отправить в OSM»**: копирует геометрию в
   формате, который остаётся вставить в редактор OSM. Дорога, отданная в OSM,
   поддерживается всем миром, а наша — только нами.

Это и есть «умная функция, которая сама всё настраивает»: она не решает за
человека, но не даёт забыть.

## 7. Ворота перед публикацией

К уже существующим воротам дорог (`roads_gate.py`) добавляются свои. Числа
подобраны так, чтобы ловить опечатку, а не мешать работе:

| Проверка | Порог |
|---|---|
| Объект дальше от любой дороги | 30 м → стоп |
| Светофор не на узле | предупреждение, не стоп |
| Разворот на односторонней | стоп |
| Полос меньше 1 или больше 8 | стоп |
| Своя дорога короче | 20 м → стоп |
| Отпечаток не сошёлся | не публикуется до проверки |
| Изменилось правок за раз | > 200 → стоп и вопрос |
| Объектов в одном тайле | > 500 → стоп: похоже на клик-спам |

Правка, не прошедшая ворота, **не пропадает** — остаётся в таблице и попадает
в очередь.

## 8. Производительность: правила с числами

1. **Каждый вид — свой набор в тайле, своя полоса охвата, своя ступень
   перегрева.** Уже так живут дворы, вода, зелень, рельсы, кварталы; точки
   добавлены тем же способом.
2. **Светофор виден до 260 м, разворот до 340.** Дальше это пиксель среди
   сотни таких же, то есть шум.
3. **Правки запечены** — на телефоне ноль работы сверх отрисовки.
4. **Пиктограммы объявлены символами Canvas** — растеризуются один раз на
   растр, дальше только копируются. Сто светофоров стоят одной растеризации.
5. **Ничего в `RebuildKey`, что меняется чаще растра.** Правило не нарушалось
   ни разу и не нарушится.
6. **Бюджет на вид в тайле.** Больше порога — режем по близости, как режется
   сеть в перегреве.
7. **Панель работает по видимой области.** В тайле Ташкента 71 595 дорог;
   попытка показать страну убьёт её на первом открытии. Запрос — по рамке
   карты, с потолком в 2 000 объектов на экран.
8. **Магнит ищет по сеточному индексу**, а не перебором: тот же приём, что у
   `TileRoadNetwork`, ячейка 0.01°.

## 9. Редактор: как он устроен

### 9.1. Две подложки, и вторая важнее

**Спутник Яндекса** — чтобы видеть правду: где на самом деле светофор.
**Наш собственный рендер схемы** — чтобы видеть, что увидит водитель.

Без второго рисуешь вслепую: объект, идеально поставленный по спутнику, на
схеме может оказаться под дорогой, за краем охвата или неотличимым от соседа.
Переключение — одной клавишей, обе подложки в одном масштабе.

### 9.2. Порядок работы

1. Выбрать вид объекта (панель слева, горячие клавиши 1–9).
2. Вести курсор — магнит подсвечивает дорогу, к которой прилипнет, и рисует
   призрак объекта в том виде, в каком он попадёт на телефон.
3. Клик — объект создан со статусом «черновик».
4. Карточка справа: свойства по виду, обязательное «почему» для своей
   геометрии, кнопка «принять».
5. Перетаскивание — объект переставляется, магнит работает так же.
6. Клавиша Delete — статус «снято», не удаление.

### 9.3. Чего в редакторе не будет

- **Свободного рисования без магнита** — кроме явного режима «вне дороги».
- **Массовых операций** без предпросмотра списка.
- **Публикации.** См. закон 2.

## 10. Этапы

| Этап | Что | Цена |
|---|---|---|
| **0. Светофор насквозь** | таблица, редактор с магнитом, экспорт, запекание, ворота, отпечаток. Клиентская половина **готова** | 2 дня |
| 1. Остальные точки | лежачий, стоп-линия, разворот — новых механизмов ноль | день |
| 2. Очередь изменений OSM | `osm_diff.json`, страница «Что изменилось», авто-пересадка | 2 дня |
| 3. Свойства дороги | полосы (пузырь уже готов), односторонность, уровень | 2 дня |
| 4. Своя геометрия | с пометкой, «почему», сроком и кнопкой «отправить в OSM» | 2–3 дня |
| 5. Камеры переезжают | один инструмент вместо двух | день |

**Нулевой этап — не про светофор, а про цепочку.** Пока «панель → таблица →
тайл → телефон → и обратно через очередь изменений» не работает целиком,
добавлять виды бессмысленно: каждый следующий унаследует её ошибки.

Второй этап стоит делать раньше третьего, хотя он и скучнее: без очереди
изменений слой начнёт тихо расходиться с OSM с первого же воскресенья, и
через месяц никто не вспомнит, что где нарисовано.
